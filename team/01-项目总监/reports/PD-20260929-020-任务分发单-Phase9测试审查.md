## 测试点清单（20 点，总监定稿——交付报告逐点给证据）

### A 组 · §11 七端点契约（点 1–6）

1. **七端点登记与包络**：`task-breakdown` / `schedule-suggestion` / `expense-parse` / `review-summary` / `confirm` / `cancel` / `usage` 路由与 §11 逐端点对照（方法、路径、§1.2 成功包络、§1.4 错误语义），架构测试「每路由都登记接口文档」覆盖 7 条不漏；§11 之外 `app/api/v1/ai` **零新增端点**。
2. **task-breakdown 边界**：正常生成（`draft_id`/`status=pending`/分组 suggestions）；`tasks` 缺省或空数组 → 400；`min(1)/max(20)` 越界 → 400；title 超 `TASK_TITLE_MAX` → 400（**复用既有约束不新造**）。
3. **schedule-suggestion 与 C2 落点**：正常建议包；建议块落 `source='suggested'`；逐条接受/拒绝走**既有** `POST/DELETE /schedule-blocks`（披露 3 实证——不新增端点）。
4. **expense-parse 与失败态**：金额/分类解析正确；生成失败 → **200 + `suggestions=[]` + `status='failed'`**，`error_code` 回落 `result_json.error_code`，**`detail` 不含上游原文**——空载荷不冒充成功。
5. **confirm 状态机**：pending → 写入成功（`tasks` 分组体 min1/max20、`confirmed_at` 落值）；**failed → 422 `VALIDATION_ERROR`**（语义校验约定同源，非自造状态码）；confirmed/cancelled → 409；expired → 409；服务端权威字段回带、不接受客户端覆盖。
6. **cancel + usage**：cancel pending → cancelled、任一终态 → 409（failed 口径按 §11 实文）；usage 额度窗口＝**用户时区自然月**、月限两枚触顶 429、`AI_RATE_LIMIT_PER_MINUTE` 速率触顶 429、Mock 模式计 `skipped` **不占额**。

### B 组 · 迁移与数据（点 7–9）

7. **迁移 `0007`**：forward-only、`ai_drafts` + `ai_usage` 两表与索引齐、既有迁移零改动。
8. **§4.13 CHECK 三枚**：`status='failed' OR result_json IS NOT NULL`（总监补正等价——非 failed 必非空、failed 可空）、`status<>'failed' OR error_code IS NOT NULL`（裁定 4）、`draft_type IN` 四值；**确无 `version`/`deleted_at` 列**（裁定 5）。
