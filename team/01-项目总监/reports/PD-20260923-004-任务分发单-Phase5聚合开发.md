## 终审冻结口径（逐条执行，不得超出）

1. **范围基准**：本地单用户 × 多设备同步；云端账号/认证/邮件通道/真实跨用户隔离继续挂账（`/auth/cloud/*` 与 401 保留云端语义，不实现）。
2. **Service Worker 不进本批**；SYNC-002 验收口径 = 「已打开页面断网续用」（详设 §5.4.3 实测结论），「刷新/重开页面离线可用」明确排除在验收外。
3. **manual_merge 不做 UI**：resolve 端点保留枚举，前端无第三按钮、无占位。
4. **服务端 `outbox_operations` 不落地（终审确认）**：Phase 5 迁移只建 `sync_conflicts` 与按需索引，**不建 `outbox_operations`**；幂等唯一落点 `idempotency_keys`（`key = "sync:" + operationId`，`sync:` 为保留前缀）。表定义保留不删。
5. **文案唯一准据 = UI 规范 v0.20 §4.9.1/§4.9.2/§4.9.3 冻结文本**（终审确认）；不得采用详设 §5.4.3 的建议措辞（「N 项修改待同步」「已恢复联网」Toast、离线态扩写均不采纳）。已知边界接受：离线态独占横幅时，本地写入的「已存本机」告知依赖写入成功反馈，联网后由状态 3/4 呈现。
6. **冲突二选不可撤销 + 主按钮「保留此设备版本」（终审确认）**；「稍后处理」为初始焦点；说明行「选择后另一版本将被覆盖，此操作不可撤销。」不可省略。
7. **S2 安全滞后窗口是唯一正确性前提**：pull 必须落 `changeAt <= now() - lag`（默认 5s 可配）查询条件；测试须构造「后提交但 changeAt 更早」场景断言仍能拉到。
8. **命名消歧**：客户端 IndexedDB store 一律称 `pending_operations`（详设 §5.4.2）；服务端表名 `outbox_operations` 仅存在于不启用的定义中，代码中不得出现混淆命名。
9. **S1 选型**：原生 IndexedDB + 项目内薄封装 `LocalStore` 端口，**零新依赖**（若实现中确需引入依赖，停止并上报，lockfile 官方源纪律见事故记录 002）。
10. **SYNC-005 验收形态**：局域网/双浏览器（同机双浏览器 profile 或手机经局域网访问开发服务器）四条验收；真机 PWA 挂 Phase 10，不在本批。

## 任务内容（任务 ID：SYNC-001~005，聚合开发）

### SYNC-001 云端仓储和 API（P0）

- [ ] 实现接口文档 §12 三端点：`POST /sync/push`、`GET /sync/pull`、`POST /sync/conflicts/{conflictId}/resolve`，按 §12.1 勘误口径——push 逐条返回 `applied | already_applied | conflict | rejected`（HTTP 整体 200，单条失败不回滚整批）；pull 游标为不透明字符串 `"<changeAt毫秒>:<uuid>"`、keyset 分页、`limit ≤ 100`、安全滞后窗口、客户端按 `(entityType, entityId, version)` 幂等 upsert。
- [ ] 「云端主数据源/REST/写返回 version/用户数据隔离」四项按 PD-20260923-001 裁剪说明——已由 Phase 2-4 提前实现，本任务只补 sync 端点与增量拉取，不做真实跨用户隔离（挂账）。
- [ ] 跨表 pull 按 `entity_type` 分组 UNION 统一排序；墓碑四类传递按 DB §4.18.1 表执行；所有写路径（含软删、取消）经 Drizzle `update()` 使 `changeAt` 前进。
- [ ] 索引按 DB §4.18.1（4）评估：`tasks` 已有，其余表按需在 Phase 5 迁移补 `(user_id, changeAt, id)`。

### SYNC-002 IndexedDB 缓存（P0）

- [ ] 原生 IndexedDB 薄封装三 store：`entity_snapshots` / `pending_operations` / `sync_cursor`（详设 §5.4.1/§5.4.2）；schema 升级走 `onupgradeneeded` 集中迁移函数；「一次读改写同一事务」收敛为可测规则。
- [ ] 保存最近查询数据与待同步草稿；显示缓存和待同步状态——按 UI 规范 §4.9.1 六态横幅（复用 §4.7 唯一容器、状态互斥、优先级、计数口径、按钮层级、Toast 分工、ARIA 规则逐条照做，零新增令牌）。
- [ ] 核心页面网络失败不白屏 + **离线续用按已冻结口径验收**：已打开页面断网 → DOM 未变、离线提示条出现、已预取路由可切换；e2e 不得写成「断网刷新后仍可用」。
- [ ] **补测（终审要求）**：在有真实数据（PG 可用）的环境补测「有数据时的断网续用」表现（RD-20260923-001 环境限制项），结论写入交付报告。
- [ ] 架构断言扩展：页面不得直接访问 `indexedDB`，只能经 `LocalStore` 端口。

### SYNC-003 Outbox 和幂等提交（P0）

- [ ] 客户端操作生成 UUID（operationId），入 `pending_operations`：操作类型、实体 ID、基础版本、payload。
- [ ] 网络恢复后批量提交（刷新时机按 §4.9.1：online 事件、页面可见、手动「立即同步」、本地写入入队；自动重试仅前两类，不做后台无限循环）。
- [ ] 重复提交不产生重复写入：`idempotency_keys` `key = "sync:" + operationId`、指纹 `sha256(entityType | entityId | operationType | payload)`；同 key 异指纹 → 该条 `rejected`；已 completed 同指纹 → `already_applied` 回放快照。
- [ ] `sync:` 保留前缀在普通写请求侧有校验或断言，防止占用。

### SYNC-004 冲突处理（P0）

- [ ] 任务/目标版本冲突检测（baseVersion/version 机制已有）→ 生成 `sync_conflicts` 记录，push 返回 `conflict`。
- [ ] 时间块冲突提示：SCHED-002 已实现，本批只做回归确认并在报告中说明。
- [ ] 执行记录追加式处理（**开销部分顺延 Phase 6**，本批不涉及 expenses）。
- [ ] 删除墓碑在 pull 链路传递（DB §4.18.1 四类表）；级联硬删按「父级墓碑级联清理」。
