# PD-20260929-023 任务分发单：Phase 10 批 A·甲案（完整云端账号）专项详设

## 一、背景与拍板

2026-10-09 最终决策者第一拍板：**甲案——完整云端账号**（口定「完整账号吧」）。乙（独立实例）、丙（最小认证层）出局，一轮制：邀请测试直接建在完整账号上。拍板全文与批次结构见 `PD-20260929-016` 变更记录 2026-10-09 条（五项生效口径），本单不重复，**以该条为准据**。

执行默认子口径（候终审一词确认，详设按此推演并标注切换点）：

1. **认证方式＝邀请制 + 邮箱密码 + 邀请码激活**——不做公开注册（决策清单首轮邀请制）、不接社交登录（T-006 不变）、魔法链接为可切换项（切换代价须在详设中量化）；
2. **验收红线＝开放部署关闭自动本地会话**：`EnsureLocalSessionUseCase` 加门，未登录 401 → 登录页；本地自用/开发部署维持现状——以「部署形态开关」承载；
3. **邮件通道分阶段**：邀请投递首版可手工分发（复制链接/邀请码），密码重置等邮件随批引入——成本对照 SRS §7.2 预算。

## 二、任务：甲案专项详设（唯一交付，只读）

对齐 spike `RD-20261006-010` §4.2 四层 + §6.2 十二项 + §8.2 八项，交付以下 7 项：

| # | 交付项 | 要点 |
|---|---|---|
| 1 | **schema 详设** | `invitations` / `sessions` 完整形态（甲案＝可吊销 + 多设备 + 设备标签，详设 §8.1 L620「云端批次重定」的兑现）+ `users` 加列（`password_hash`、`email_verified_at`、`deleted_at`）；迁移批次对标 DB-001；**与 data-management 批 `deleted_at` 的归属划分**（两批不得加同一列两次） |
| 2 | **认证流程时序** | 邀请生成 → 分发（手工起步口径）→ 激活设密 → 登录 → 会话签发/续期/吊销 → 密码重置（邮件分阶段）；**会话固定防护**（登录成功轮换 token） |
| 3 | **端点详设** | `/auth/cloud/*` 契约兑现（`request-link` 与实际形态对齐，或以清单形式提请勘误）；`/me` 401/403 强制路径（详设 §8.1 L621 预留位）；限流与枚举防护点；登出/吊销 |

| 5 | **批次拆分建议** | 四小批 DB → auth → UI → 测试的边界、依赖、commit 序列（单 PR 多 commit）；与批 1/批 2/批 3 的并行排布（对齐 PD-016 批次结构） |

### 护栏（与 spike 分发单同源）

- **只读详设**：零产品码、零契约文档改动——doc/05/doc/06/SRS 勘误一律以清单形式提请，由 PM 升版落卷；
