## 1. 测试范围与策略

### 1.1 范围

- SYNC-001~005 全部任务（pull/push/resolve、LocalStore、六态横幅与冲突浮层、幂等与冲突、墓碑传递）
- SYNC-000 spike 结论验证（S1 零新依赖、S2 安全滞后窗口、S3 `sync:` 前缀与 `pending_operations` 命名消歧、S4 离线边界口径）
- UI-008 规范符合性验证（§4.9 六态横幅、冲突浮层、Toast 分工）
- ConfirmDialog 默认行为回归（RD-20260923-002 裁定 4 承诺项）
- db:test 陈旧断言修复

### 1.2 分层策略

| 分层 | 职责 | 本次覆盖 |
|------|------|----------|
| **Unit** | 纯逻辑、domain/application 层、架构断言 | 测试点 2、3、4、5、6、7（单元部分）、8、11、12、16、17、18 |
| **Integration** | 组件行为、API 路由、MSW 拦截 | 测试点 1、7（集成部分）、10、15 |
| **E2E（node:test）** | 结构断言、契约冻结 | 测试点 14（db:test 修复） |
| **E2E（Playwright）** | 真实浏览器、双视口、离线模拟 | 测试点 9、10（e2e 部分）、13、15 |

### 1.3 执行顺序

1. 修复 db:test 陈旧断言（测试点 14），跑 `npm run db:test` 确认全绿
2. 新增 unit 用例（测试点 2、3、4、5、6、7 单元部分、8、11、12、16、17、18）
3. 新增 integration 用例（测试点 1、7 集成部分、10、15）
4. 新增 e2e 用例（测试点 9、10 e2e 部分、13、15）
5. 跑 `npm run check` 收集 unit/integration/node:test 计数
6. 跑 `npm run test:browser` 收集 desktop/mobile 计数
7. 专项 A：SYNC-005 局域网形态复核（测试点 13）
8. 若局域网复核通过，勾选 doc/06 SYNC-005 四框
9. 写 QA-20260924-001 测试报告

## 4. 依赖与环境要求

- Node.js 20+（项目固定版本）
- PostgreSQL 17（Docker `livefil-pg` 已运行，端口 55432）
- `TEST_DATABASE_URL` 环境变量（由 `scripts/env/db.mjs` 驱动 `npm run db:test`）
- Playwright Chromium 已安装（`.cache/playwright/`）
- 局域网复核需要：手机或第二台设备可访问开发服务器地址
