## 2. 六项交付摘要（PD-029 §二 逐项）

### 2.1 注册流改造（第 1 项）

`POST /auth/cloud/register` 字段改 **`{inviteCode, username, displayName?, password, email?, code?}`**——email/code **双态**（`emailEnabled` 驱动）：

- **降级态**（无 `EMAIL_API_URL`）：email 选填、不核码、不发信；`emailVerifiedAt` 恒 `null`（免验证不写验证时刻，诚实优于冒充）。
- **全形态**（配好 `EMAIL_API_URL`）：email + code 必填并**真核码**（拍板 3「三步注册回归」的验证能力，非假流程）；核码通过 ⇒ `emailVerifiedAt=now`。

**CHECK 经新迁移 0010 放宽**（0008 禁改）：`mode='local' OR password_hash IS NOT NULL`——email 移出判据（可空）、密码仍是 cloud 硬要求；`toCredentials` 可认证判据随之从 `email!==null` 改为 `passwordHash!==null`（否则无邮箱 cloud 用户被误挡在登录/改密外）。

### 2.2 邀请码门（第 2 项）

`INVITE_CODES` env（逗号分隔、trim+小写+滤空+**去重**归一；未配置＝空集合＝注册全拒）；**无码/错码统一 400 文案**「邀请码不正确。」（防枚举——不区分缺失/为空/不匹配，`RegisterUserUseCase` 单点判定）；注册 **IP 限流保留**（双闸）；作废＝改配置重启；`invitations` 全版表结构候补不进本批；码熵入安全矩阵（spike §6.2 丙案转正）。

### 2.3 邮件分阶段开关（第 3 项）

`EMAIL_API_URL` ＝**单一分支点**（`serverEnv.emailEnabled`）；未配置⇒降级态、已配置⇒全形态**自动回归**（读 env、无硬编码、改配置重启即生效）。**生产红线显式化**：`production+cloud+显式 EMAIL_PROVIDER=mock` 才拒（降级态缺省 provider 不误伤）；**反向绑定**（新增 refine）：配邮件三件任一 ⇒ 必须 `EMAIL_PROVIDER=http`，使 `http ⟺ 三件套齐 ⟺ URL 已配置`——半配置装配期拒绝，「配置与行为一致」。

### 2.4 UI 注册页与 (auth) 适配（第 4 项）

- **注册页双态**：降级态＝邀请码 + 账号 + 名字 + 密码（单表单，分发单第 4 行四项）；全形态＝邀请码（步 1 与邮箱同收）+ 原三步邮箱验证。

- **忘记密码页降级态**：整页替换为「当前部署未开通自助重置，请联系管理员重置密码。」。
- 三页 `force-dynamic`（每请求读 env，形态不被静态固化）。
- **冻结文案零改动**；结构增减与新增文案逐条入 §4 对照表（供 PM 注记）。

### 2.5 安全面（第 5 项）

邀请码熵（部署侧 8+ 位随机建议）+ 注册 IP 限流 + 统一文案三件入矩阵；免验证滥用面＝**码门 + 限流双闸**声明；原 22 行安全落点零回归。详见 §5。

## 5. 安全面（PD-029 第 5 项）

1. **邀请码熵**：`INVITE_CODES` 部署侧生成建议 **8+ 位随机**（spike §6.2 转正）；env 解析 trim+小写+滤空+去重归一，比对对输入同归一（大小写不敏感）。
2. **注册限流**：IP 10 次/小时（`RATE_LIMITS.registerPerIp`）**保留**——与码门构成免验证后的**双闸**（原「验证码门槛」职责移交）。
3. **统一文案三件**：邀请码「邀请码不正确。」（无码/错码同句）、核码「验证码不正确或已过期。」（全形态）、限流「操作过于频繁，请稍后再试。」——均防枚举、不区分失败型。
4. **免验证滥用面**：码门（秘密，8+ 位熵）+ IP 限流双闸声明；`invitations` 全版表结构（逐码撤销/过期/审计）候补，当前简版以「改配置重启」作废。
5. **枚举门槛降级（如实披露）**：username 撞名 409 的原前提「已持有效邮箱验证码（控制邮箱门槛）」随免验证消失，降为「邀请码 + IP 限流」——409 字段级提示「该账号名已被使用。」保留（护栏 4 主体零回归），持码者可枚举 username 的面扩大，由码熵 + 限流兜底（PM/终审知情）。
6. **原 22 行安全落点零回归**：登录/会话固定/吊销/隔离/日志脱敏/邮件边界一概未动；`login-user`/`send-verification-code` 的 `email===null` 分支是**新增**防御（对有邮箱用户零变）。
