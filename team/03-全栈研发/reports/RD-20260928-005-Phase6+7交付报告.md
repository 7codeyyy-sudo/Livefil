## 三、交付内容

### 3.1 服务端

- **迁移（只向前）**：`0004` 建 `expense_categories` / `expenses`；`0005` 建 `reviews` / `review_adjustments`。两表各带 keyset 索引 `(user_id, updated_at, id)`；`reviews` 带普通唯一索引 `unique(user_id, review_type, period_key)`（**不建 `deleted_at`**，C.4 采 B）。
- **开销**：分类惰性 seed（该用户无任何分类行时落 9 项默认分类）、改名、停用（`is_archived`）；开销金额为最小货币单位整数（DB `bigint`），`user_id` 作用域贯穿所有查询，`occurred_on` 按用户时区落日期，列表游标分页，汇总按 `category | lifeArea | goal` 三档。
- **复盘**：日复盘 upsert（唯一键收敛）、周复盘「事实」计算与快照 schema v1（物化时机见 §四①）、调整**记录 + 执行同事务**。
- **端点**（13 个 handler）：`GET/POST /api/v1/expenses`、`PATCH/DELETE /api/v1/expenses/{id}`、`POST /api/v1/expenses/{id}/restore`、`GET /api/v1/expense-summary`、`GET/POST /api/v1/expense-categories`、`PATCH /api/v1/expense-categories/{id}`、`GET/PUT /api/v1/reviews/daily/{date}`、`GET /api/v1/reviews/weekly/{weekStart}`、`POST /api/v1/reviews/weekly/{weekStart}/adjustments`。
- **关键口径**：金额跨线（DB `bigint` ↔ 接口字符串 ↔ 快照 payload ↔ 入队记录）**一律字符串，任何环节不经 `Number()`**；混币**按币种分列不合计**；`groupBy=goal` 按 `goal_id` 单列分组（无需 JOIN `actions`，与 `tasks` 两列并存口径一致）。

### 3.2 客户端

- **`/expenses`（A1~A6）**：金额优先输入、默认分类 + 最近使用分类分组、日期/支付方式/备注、编辑与软删、删除后撤销 Toast、分类管理（改名/停用）、加载更多、筛选。
- **`/review`（B0~B4）**：B0 日/周两段；B1 日三问 + 精力三档（只答一题即可保存，「跳过今天」纯前端不落记录）；B2 周七项（含按币种分列 + 按分类 + 按生活领域三块开销）；B3 三条洞察与行尾「调整」+ 行内展开的动作组；B4 五动作 ConfirmDialog（`destructive` 仅删除、`initialFocus: cancel`）、追加式调整清单、固定文字链接「查看下周计划」。
- **令牌纪律**：新增 6 个 `.module.css` 只引用 `tokens.css` 令牌，无颜色/时长/圆角/字号/层级字面量；`ui-001-acceptance.mjs` 13 项全绿。

### 3.3 同步接入扩展（披露 B）

- `SYNC_ENTITY_TYPES` 追加 `expense` / `review`；实体注册表追加两条 spec（expense `soft-delete`、review `unsupported`）；客户端 `SYNC_ENTITY_BY_COLLECTION` 映射表追加两项（**正则不动**，B.2 技术更正经采纳）。

## 八、建议测试点清单（交测试交付岗落用例，12 条）

1. **页面禁访 indexedDB**：`/expenses`、`/review` 及其组件不得直接访问 `indexedDB`（扩 `indexed-db-access` 断言）。
2. **金额跨线零 float**：超 2^53 附近大额字符串往返、两位小数边界；payload / 快照 / 入队记录中金额始终为字符串，源码扫描不得出现 `Number(amountMinor)`。
3. **分类语义**：惰性 seed 9 项默认分类（触发条件为「该用户无任何分类行」）；改名；停用后历史开销仍可回填并带「已停用」标记；**无 DELETE**（3 个 handler 之外不存在删除路径）。
4. **作用域隔离**：跨用户 id 读取/编辑分类与开销不可达；全部查询带 `user_id`。
5. **`occurred_on` 时区**：跨日与补记按用户时区落日期，无时区歧义。
6. **汇总口径**：`groupBy=category|lifeArea|goal` 三档；**混币分列不合计**；软删不计入。
7. **软删与撤销**：`DELETE` 后列表不显示且汇总不计入；`restore` 回滚；**离线删除失败 → 行不移除 + 明确失败提示 + 不弹撤销 Toast**。
8. **日复盘读写**：未填写返回 `data: null`（**200 非 404**）；`answers` 三键均可省、空串按未答；`answers` 与 `energyLevel` 同时为空 → **422**；PUT 幂等（唯一键收敛，不重复建行）。
9. **离线记日复盘（甲案）**：离线 `PUT` 入队 → 恢复网络 push 落行；同日在线再 `PUT` **收敛同一行**不重复建。
10. **周快照**：过去周首次访问物化 + **写入后不重算**；**当周不落库**；`schemaVersion` 不匹配的存量行按重算处理。
11. **调整同事务**：五动作 `payload` 校验（`shorten` 正整数分钟、`defer` 截止日）；`action`/`targetType` 不匹配 → 422；执行失败**整体回滚**（目标已不存在/并发变更）；返回入列后完整清单；**无撤销端点**；离线提交明确失败。
12. **冲突闭环**：expense 金额冲突 → push 返 `conflict` → `keep_local` / `keep_server` 均收敛（含 `keep_server` 正路径）；冲突摘要含「金额/币种/日期」三行；实体名不退化 UUID。
