### Spike 任务（4 项，每项给出：结论 / 理由 / 影响 / 回退方式）

1. **S1 IndexedDB 封装选型**：原生 IndexedDB / idb / Dexie 对比。结论须覆盖：事务语义、schema 升级路径、与 React 19 并发特性的兼容、是否引入新依赖（若引入，注明 lockfile 必须走官方源纪律——本阶段只写结论，不安装依赖）。
2. **S2 增量拉取游标机制**：per-entity `updated_at` 扫描 vs 统一 change-log 表。单用户场景推荐最小方案（**不预造 change-log 表**，除非有不可辩驳的理由）；须处理同刻并发写入的游标单调性与软删墓碑在 pull 链路的传递。产出数据库设计文档勘误草稿。
3. **S3 push 幂等整合与命名消歧**：operationId（客户端 UUID）与 `already_applied` 判定的落点——复用 `idempotency_keys`（key + request_hash 指纹）还是服务端 `outbox_operations` 表，二者职责不得重叠（DB §4.15 已有"与 outbox 的幂等列不重复"原则）。同时消歧：`outbox_operations` 在 DB §4.14 是服务端表（含 user_id FK）、在详设 §5.1 是客户端 IndexedDB 结构，同名不同物——给出两端命名区分方案。产出 DB + 接口文档勘误草稿。
4. **S4 离线白屏边界实测**：无 Service Worker（终审已定）下，「已打开页面断网续用」与「刷新/重开页面离线白屏」的真机实测结论；输出页面级提示文案建议（供 PM 分发单任务 1 的待同步文案对齐，注意交叉引用 PD-20260923-002）。
