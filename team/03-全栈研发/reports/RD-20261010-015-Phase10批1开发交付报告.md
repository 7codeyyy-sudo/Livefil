## 5. OPS-003 安全检查报告（五项，逐项证据 + 结论）

**范围**：批 1 结构面（RD-012 §6.3 切分——真测面归 AUTH-004/批 3 前评审）。

### 5.1 用户越权（模式无关面复核）

- **证据**：`tests/unit/architecture/repository-user-scope.test.ts`（IAM-004 静态判定）随 `unit` **422/422** 全绿——该断言扫描 `src/modules/*/infrastructure/*repository*.drizzle.ts` 的每个 `.where(...)` 必须含 `userId` 或 `@user-scope-exempt` 标记；批 1 新增的 `export-reader`/`import-gateway`/`recycle`/`deletion-request` 四个 drizzle 仓储**全部通过**（422 含新文件扫描）。`user-scope-rules.ts` 的守恒判定（from/update/delete 计数 ≤ where 计数）同步绿。
- **结论**：模式无关面（`user_id` 谓词纪律）零违规；**云端真测**（跨用户隔离实机）归 PD-027 组 1（AUTH-004），不重复。

### 5.2 SQL 注入 / XSS / CSRF

- **SQL 注入**：**用户输入直插 `sql\`` 模板 0 处**（C3 勘误口径）——`src/modules/**` + `src/infrastructure/**` 内的 `sql\`` 出现均为**列引用/固定片段辅助**（如 `${tasks.deletedAt} is not null`、`${tasks.version} + 1` 自增等 drizzle 合法用法，总监抽样 10/10 全为列引用），零用户输入直插；用户输入一律走 drizzle 参数化 `eq()`/`values()`/`inArray()`；`drizzle/schema.ts` 的 `sql\`` 仅用于 DDL 约束/索引定义，非用户输入面；外部输入全部经 zod schema（接口 §14「所有外部输入使用 schema 校验」）。
- **XSS**：`dangerouslySetInnerHTML` **0 处**（React 默认转义；无裸 HTML 注入）。
- **CSRF**：会话 Cookie `SameSite=Lax`（`session-cookie.ts`）——跨站写请求不携带 Cookie；无自定义跨站 token 需求（SameSite 足够，同站部署）。
- **结论**：三类基础注入面静态审计零命中。

### 5.3 前端包零密钥

- **证据**：`.next/static/**/*.js`（客户端包）扫 `AUTH_SECRET|EMAIL_API_KEY|postgres://|scrypt$` —— **0 处**（服务端密钥/连接串/哈希未进客户端包；`server-only` 守卫 + 组合根不入客户端图）。
- **结论**：客户端产物零密钥泄露。

### 5.4 日志脱敏

- **证据**：`src/shared/telemetry/redaction.ts` 的 `redactRecord`/`isForbiddenFieldName`（forbidden 清单含 `password`/`token`/`apikey`/完整 AI prompt/开销备注/目标理由）。运行时抽验探针（`.runtime/pd028-redaction-probe.ts`）：**10/10 PASS**——`password`/`token`/`apiKey`/`newpassword`/嵌套 `password` 全 `[REDACTED]`，`email`/`username`/`note`/嵌套 `title` 保留。
- **结论**：脱敏清单与运行时行为一致；批 1 安全事件（`DATA_EXPORTED`/`DATA_IMPORTED`/`ACCOUNT_DELETION_*`）经 `AuditLogger` 只记结果 + 匿名标识。

### 5.5 依赖漏洞扫描（C1/C2 销证后勘误）

- **勘误（C1）**：初报「`npm audit --json` → `vulnerabilities: {}`（**零漏洞**）」系**假绿**——当时命令未指定 `--registry`，走本机默认**便携 npm 镜像 registry**，其 audit 端点返回空结果（NOT_IMPLEMENTED 类），未真正查询官方 advisory DB。**定性留痕**：当时原始输出 `vulnerabilities: {}` ＝镜像端点假绿，非真实零漏洞。
- **官方 registry 重跑**（`npm audit --json --registry=https://registry.npmjs.org`）真实 `metadata` 原始段：
  ```json
  {"vulnerabilities":{"info":0,"low":0,"moderate":4,"high":7,"critical":1,"total":12},"dependencies":{"prod":40,"dev":605,"optional":167,"peer":0,"peerOptional":0,"total":682}}
  ```
  `next` 16.3.5 → **critical**（range 16.0.0-16.3.7）：next/og RCE + `use cache` Draft Mode leak + SSG/ISR cache poisoning（self-hosted 跨用户投毒）+ dev MCP info disclosure。
- **C2 修复**（预审授权）：(a) `npm audit fix`（非 `--force`）12→10（修 2 个非 major 传递依赖；next 因精确 pin `"16.3.5"` 在 range 外未动）；(b) **next 16.3.5→16.4.0** + `eslint-config-next` 同步 16.4.0（拍板修，`2552c97`）→ **critical 清零**。修后官方 registry metadata：
  ```json
  {"vulnerabilities":{"info":0,"low":0,"moderate":4,"high":5,"critical":0,"total":9}}
  ```
- **剩余 9 定性**：全部 `isSemVerMajor:true`（fix 为**降级到旧 major**，非授权且 breaking）——`drizzle-kit`/`esbuild`/`@esbuild-kit/*`（moderate，构建工具链）与 `eslint-config-next`/`@next/eslint-plugin-next`/`braces`/`fast-glob`/`micromatch`（high，lint 工具链），**均为 dev 依赖、不入生产运行时**；生产面 prod（next/react）critical 已清零。
- **结论**：生产面（prod）零 critical（next 16.4.0）；剩余 9 为 dev 依赖且 fix 需 major 降级（超本批授权、非部署运行期风险面），留 Gate E 前或工具链升级批次处置；零新依赖（护栏 1——升级系同包 minor，非新增包）。
