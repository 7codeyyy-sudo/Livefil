# Livefil 产品设计说明书

> 版本：v0.1  
> 日期：2026-09-15  
> 设计范围：第一阶段 PC Web，预留移动端  
> 关联：[需求规格说明书 SRS](../03-requirements/需求规格说明书_SRS.md)

## 1. 产品定位

Livefil 是一个面向个人用户的生活管理系统，将日程、目标、习惯、执行记录、开销和复盘连接起来。

核心承诺：

> 把今天想做的事安排得更现实，做完后用几秒记录，到了周末知道下周该怎么调整。

产品不追求让用户记录一切，而是帮助用户形成一个低负担闭环：

```text
收集想法 → 组织目标 → 安排今天 → 执行记录 → 复盘调整
```

## 2. 设计原则

1. **下一步优先**：用户打开首页后立即知道现在或接下来做什么。
2. **现实主义排程**：支持缓冲、空白时间、延期和最低版本，不鼓励把一天填满。
3. **记录产生行动**：数据只有在能帮助用户作出下一步调整时才展示。
4. **恢复优先于惩罚**：中断后帮助用户重新开始，不把连续打卡归零作为核心反馈。
5. **先行动后完善**：先允许用户完成最小记录，分类和关联信息可以后补。
6. **AI 可控**：AI 只能给建议或生成草稿，不能未经确认修改正式数据。
7. **跨端预留**：PC Web 先行，但信息架构、设计令牌和 API 不能绑定单一设备。
8. **隐私默认**：财务、目标、心情和复盘内容默认私有，可导出、可删除。
9. **减少 AI 味**：让真实任务、时间、金额和下一步行动成为主角，AI 只作为上下文辅助，不用科技装饰替代产品价值。

## 3. 信息架构

### 3.1 一级导航

| 页面 | 主要问题 | 核心操作 |
|---|---|---|
| 今日 | 现在和接下来做什么？ | 开始、完成、延期、添加 |
| 收件箱 | 还没整理的想法有哪些？ | 快速记录、安排、归档 |
| 目标 | 我正在推进什么？ | 创建目标、拆解行动、查看进度 |
| 开销 | 钱花到哪里了？ | 快速记账、分类、关联目标 |
| 复盘 | 这周发生了什么？下周怎么调？ | 查看偏差、确认调整 |
| 设置 | 我想如何使用和保护数据？ | 账户、提醒、语言、导出、隐私 |

### 3.2 PC Web 布局

```text
┌──────────────────────────────────────────────────────────────┐
│ Logo / 当前日期                         快速添加  用户菜单     │
├───────────────┬──────────────────────────────────────────────┤
│ 一级导航       │ 页面标题                         主要操作       │
│ 今日           │                                              │
│ 收件箱         │ 主内容区：时间线 / 列表 / 表单 / 复盘           │
│ 目标           │                                              │
│ 开销           │                                              │
│ 复盘           │                                              │
│ 设置           │                                              │
└───────────────┴──────────────────────────────────────────────┘
```

桌面端使用左侧导航和宽内容区；窄屏时导航折叠为顶部栏或底部导航。页面业务状态不依赖导航的具体布局。

## 4. 核心页面设计

### 4.1 今日页

#### 页面目标

让用户在 5 秒内知道当前行动、下一个行动和今天的计划负荷。

#### 页面区域

1. 日期和问候：简短，不占据主视觉。
2. 当前行动：名称、剩余/预计时长、开始或完成按钮。
3. 时间线：固定事项、任务时间块、当前时间线。
4. 未安排区：今天还没安排的任务。
5. 今日摘要：计划时长、已完成、待调整。
6. 快速添加：任务、开销、复盘记录。

#### 主要交互

- 点击任务打开侧边详情，不离开今日页。
- 拖拽时间块可调整时间；移动端使用编辑面板。
- 完成任务后提供“完成 / 最低版本 / 部分完成 / 延期 / 跳过”。
- 冲突只提示，不自动移动任务。
- 今日计划过满时显示“今天安排较满”，不显示惩罚性文案。

### 4.2 收件箱页

#### 页面目标

容纳暂时没有时间、分类或目标的想法，避免用户因为整理成本而放弃记录。

#### 主要交互

- 顶部输入框支持快速创建。
- 每条记录可以快速安排到日期、关联领域或转为目标行动。
- 支持批量归档和批量安排，但不默认批量删除。
- AI 拆解从输入框旁进入，结果以草稿展示。

### 4.3 目标页

#### 页面结构

- 生活领域筛选。
- 进行中目标。
- 暂停/已完成目标。
- 目标详情：理由、期限、行动、行动趋势、关联开销。

#### 关键规则

- 目标结果进度和行动完成进度分开显示。
- 目标没有行动时提示“添加本周行动”，而不是只显示空进度条。
- 目标可以暂停，不要求删除。

### 4.4 开销页

#### 页面结构

- 本月总额和最近记录。
- 分类/生活领域分布。
- 目标关联开销。
- 快速记账按钮。

#### 关键规则

- 金额是第一优先输入项。
- 分类默认提供最近使用和常用选项。
- 目标关联是可选项。
- 不把开销显示成道德评价，只描述事实和趋势。

### 4.5 复盘页

#### 页面结构

1. 本周一句话摘要。
2. 计划与实际时长差异。
3. 完成、部分完成、延期和跳过。
4. 重复延期事项。
5. 目标行动进度。
6. 开销摘要。
7. 下周调整清单。

#### 关键交互

- 每个洞察后直接提供一个动作：缩短、延期、暂停、保留或删除。
- AI 摘要必须显示为建议草稿。
- 用户可以跳过复盘，但系统不能把跳过视为失败。

### 4.6 设置页

分组：

- 账户与数据模式。
- 时间、时区、语言和货币。
- 提醒与安静时段。
- AI 使用与数据发送说明。
- 导出、导入、备份和删除。
- 隐私与服务说明。

## 5. 关键流程

### 5.1 首次使用

```text
打开应用
  ↓
选择本地模式或邀请账号模式
  ↓
选择/跳过生活领域
  ↓
创建第一个今日行动
  ↓
安排时间或保存在收件箱
  ↓
完成或记录一次状态
  ↓
看到第一次反馈
```

首次使用不要求用户创建完整目标体系。先完成一个小行动，比完成一套配置更重要。

### 5.2 计划被打乱

```text
任务无法完成
  ├─→ 改为最低版本
  ├─→ 延期到其他时间
  ├─→ 跳过并记录原因
  └─→ 删除/暂停
```

### 5.3 智能向导

```text
确定性向导：带用户完成首次使用
        ↓
上下文帮助：解释当前页面和下一步
        ↓
AI 建议：拆任务、排时间、生成复盘草稿
        ↓
用户确认后才写入正式数据
```

## 6. 产品文案规范

### 推荐

- “今天安排得比较满，可以把一项任务缩短吗？”
- “这件事要改到明天，还是保留最低版本？”
- “这是建议，你可以编辑后再保存。”
- “本周有 2 项任务多次延期，也许需要缩小范围。”

### 不推荐

- “你又失败了。”
- “连续记录已归零。”
- “你必须完成。”
- “你的自律能力很差。”

## 7. 移动端预留原则

第一阶段先做 PC Web，但以下能力必须从设计阶段预留：

- 导航可折叠为底部导航。
- 侧边详情可变为底部抽屉或全屏页面。
- 拖拽时间块必须有点击编辑替代路径。
- 快速添加按钮在窄屏保持可达但不遮挡内容。
- 表格和统计图在窄屏改为列表或纵向摘要。
- 所有可点击目标在移动端达到可用触控尺寸。
- 不使用只在鼠标悬停时才可见的关键操作。
