## 1. 视觉关键词

克制、清晰、安静、可靠、有呼吸感。

参考苹果产品的设计原则：留白、层次、内容聚焦、低干扰动效和高质量排版；不复制苹果官网的品牌标志、插画、页面素材或具体布局。

## 1.1 减少 AI 味规范

产品应该像一个经过长期打磨的生活工具，而不是 AI 生成的概念展示页。所有 AI 生成的页面和组件都必须通过以下检查。

### 明确避免

- 不使用大面积蓝紫渐变、霓虹发光、玻璃拟态和科技网格作为默认视觉。
- 不使用机器人头像、魔法棒、星星闪光和“AI 魔法”等装饰作为主要视觉语言。
- 不把首页做成聊天窗口或 AI 对话首页。
- 不用大量圆角卡片、标签、徽章和 KPI 数字填满页面。
- 不使用没有真实业务作用的仪表盘、环形图和趋势图。
- 不把所有操作都包装成“智能”“魔法”“自动化”。
- 不使用过于夸张的渐入、漂浮、脉冲和持续循环动效。
- 不使用没有内容依据的插画、人物照片或 AI 生成装饰图。
- 不让 AI 建议使用比用户任务更强的视觉层级。

### 推荐使用

- 中性色为主，一个稳定的品牌强调色为辅。
- 用排版、间距和真实内容建立层次，而不是靠阴影、渐变和装饰。
- 让用户的任务、时间、金额和下一步行动成为视觉主体。
- 使用简洁的线性图标和明确文字，不依赖图标猜含义。
- 让页面保留适度空白，不为了“看起来丰富”添加无关模块。
- AI 建议使用普通的建议区、草稿区或上下文操作，不使用发光按钮。
- 重要操作使用直接动词，例如“拆分任务”“安排时间”“保存建议”。
- 空状态提供具体下一步，不使用泛化的“开启你的 AI 之旅”。

### AI 功能的视觉层级

AI 必须是产品中的辅助能力，不是品牌主角：

1. 用户手动操作始终可用。
2. AI 入口放在任务、排程和复盘的上下文中。
3. AI 结果明确标记为“建议”或“草稿”。
4. AI 结果必须可编辑、取消和撤销。
5. AI 加载状态使用普通的进度反馈，不使用持续闪烁或发光动画。

### 去 AI 味验收清单

- [ ] 去掉无业务作用的渐变、发光和装饰图。
- [ ] 页面首屏能看见真实任务或下一步行动。
- [ ] 页面不是卡片和数字的堆叠。
- [ ] AI 不是首页唯一入口。
- [ ] AI 建议的视觉权重低于用户确认后的正式数据。
- [ ] 所有图标和颜色都有明确语义。
- [ ] 去掉无法解释的动画和“科技感”装饰。
- [ ] 文案像生活工具，而不是营销型 AI 产品。

## 2. 设计令牌

### 2.1 色彩

第一阶段使用浅色主题：

| 语义 | 建议值 | 用途 |
|---|---|---|
| 页面背景 | `#F7F7F5` | 页面整体背景 |
| 主表面 | `#FFFFFF` | 卡片、抽屉、输入区域 |
| 主文字 | `#1D1D1F` | 标题和重要内容 |
| 次文字 | `#6E6E73` | 辅助说明和时间 |
| 边界 | `#E5E5E2` | 分隔线和输入框 |
| 主强调色 | `#1769E0` | 当前状态、进度、焦点、品牌点缀 |
| 成功 | `#2D8A5B` | 完成、同步成功 |
| 警告 | `#B7791F` | 超载、冲突、待处理 |
| 危险 | `#C0392B` | 删除、错误、失败 |

颜色不能成为唯一语义载体；完成、延期和冲突同时使用文字、图标或状态标签。

**主操作配色（v0.4 定稿）**：保存、开始、确认等高强调主按钮使用**近黑实心**——底色 `#1D1D1F`、hover `#000000`、白字，**不使用强调色蓝**。原型的黑按钮已经过整体视觉验收；蓝色在本系统中专指「此刻活着的状态」（当前时间线、进度填充、焦点环），与「动作」分离，避免同屏蓝色按钮与蓝色状态互相抢夺语义，也把全页饱和色面积压到最低（§1「中性色为主，一个强调色为辅」）。

### 2.2 字体

```css
font-family: -apple-system, BlinkMacSystemFont, "Segoe UI",
  "PingFang SC", "Microsoft YaHei", sans-serif;
```

| 层级 | 字号 | 字重 | 行高 | 令牌（取值） |
|---|---:|---:|---:|---|
| 页面标题 | 28–32px | 500 | 1.25 | `--font-size-page-title`（32px） |
| 区域标题 | 18–20px | 500 | 1.35 | `--font-size-section-title`（20px） |
| 正文 | 14–16px | 400 | 1.5 | `--font-size-body`（16px） |
| 辅助文字 | 12–13px | 400 | 1.45 | `--font-size-caption`（13px） |
| 数字摘要 | 24–32px | 500 | 1.1 | `--font-size-figure`（28px） |

第一阶段仅使用 400 和 500 两种字重，避免视觉噪声。

v0.7 决策：原型 `.tag` 文字为 11px，低于五级字阶任一档下限（caption 为 12–13px），11px 中文小字可读性不足，Badge 文字归整到 `--font-size-caption`（13px）；**不新增第六级字阶**，将来确有 sub-caption 真实消费者时按「需要才落」补令牌并更新本表。

### 2.3 间距和圆角

- 基础间距单位：4px。
- 页面内边距：桌面 32px，平板 24px，手机 16px。
- 内容最大宽度：1200px。
- 几何圆角：10px、14px、20px（令牌见 §2.4「圆角令牌」表）；丸形元素（Badge、进度条等端帽完全圆化者）使用专用丸形令牌 `--radius-pill`（999px），不计入三档几何圆角。原型根变量 `--radius: 16px`（用于 `.surface`）为原型期取值，规范冻结卡片/表面圆角为 14px。
- 主要按钮触控高度：至少 40px；移动端主要触控目标建议 44px（控件高度令牌化，取值与移动端覆盖机制见 §2.4）。
- 阴影极少使用，只用于抽屉、浮层和主操作反馈。

### 2.4 设计令牌的 CSS 命名与使用约定

本节把 §2.1–§2.3 的设计令牌落到 CSS 形态（对应 T-002：原生 CSS 自定义属性 + CSS Modules）。令牌唯一定义在 `src/shared/ui/styles/tokens.css`，由应用根布局唯一导入；组件使用 CSS Modules 引用变量，不直接写字面量。

颜色令牌当前共 18 个：9 个基础语义色（对应 §2.1，逐行给出权威取值）+ 9 个派生/辅助色。UI-002 批次 2 收编 3 个状态色边框后扩为 21 个（见下文「状态色边框」）。

基础语义色（9 个）：

| 语义 | CSS 变量 | 浅色取值 |
|---|---|---|
| 页面背景 | `--color-bg-page` | `#F7F7F5` |
| 主表面 | `--color-surface` | `#FFFFFF` |
| 主文字 | `--color-text-primary` | `#1D1D1F` |
| 次文字 | `--color-text-secondary` | `#6E6E73` |
| 边界 | `--color-border` | `#E5E5E2` |
| 主强调色 | `--color-accent` | `#1769E0` |
| 成功 | `--color-success` | `#2D8A5B` |
| 警告 | `--color-warning` | `#B7791F` |
| 危险 | `--color-danger` | `#C0392B` |

派生/辅助色（9 个）：

| 语义 | CSS 变量 | 浅色取值 | 取值来源 |
|---|---|---|---|
| 柔和面（悬停/选中、标签、分段控件、进度轨道） | `--color-surface-soft` | `#F0F0ED` | 原型 `--surface-soft`，6 处使用 |
| 占位文字 | `--color-text-placeholder` | `#A2A2A7` | 原型输入框 placeholder |
| 强调色上的文字/图标 | `--color-on-accent` | `#FFFFFF` | 原型头像文字 `#fff`（主按钮白字见 v0.4 别名 `--color-on-primary`） |
| 强调色柔和底（选中态、浅底容器） | `--color-accent-soft` | `#EAF1FF` | 原型 `--blue-soft` |
| 键盘焦点环 | `--color-focus-ring` | `rgba(23, 105, 224, 0.28)` | 原型 `:focus-visible`（§7 要求焦点可见） |
| 弹层遮罩 | `--color-overlay` | `rgba(29, 29, 31, 0.28)` | 原型 modal-backdrop |
| 成功柔和底 | `--color-success-soft` | `rgba(45, 138, 91, 0.08)` | 原型完成态底色 |
| 警告柔和底 | `--color-warning-soft` | `rgba(183, 121, 31, 0.08)` | 按 soft 推导规则生成 |
| 危险柔和底 | `--color-danger-soft` | `rgba(192, 57, 43, 0.08)` | 按 soft 推导规则生成 |

`*-soft` 推导规则：**状态色柔和底 = 对应语义色在白底上按 8% alpha 叠加的快照**（`rgba(<语义色 RGB>, 0.08)`）。accent-soft 保留原型已验收的定值 `#EAF1FF`，不强行改为纯 8%。焦点环的 3px 宽度与 2px offset 是几何不是颜色，写在 base/组件样式中，不做颜色令牌。

阴影令牌（2 个，只允许这两处阴影）：

| 语义 | CSS 变量 | 取值 |
|---|---|---|
| 弹层阴影（Modal、Drawer） | `--shadow-overlay` | `0 16px 44px rgba(29, 29, 31, 0.10)` |
| 抬升阴影（Tabs 等激活项、主操作反馈） | `--shadow-raised` | `0 1px 4px rgba(29, 29, 31, 0.06)` |

其他令牌族：`--font-*`（字体族、字号、字重、行高，取值见 §2.2 字阶表令牌列）、`--space-*`（4px 倍数）、`--radius-*`（10/14/20px 几何圆角 + 999px 丸形，见下文「圆角令牌」表）。断点不做成 CSS 变量（变量无法用于 `@media` 条件）：CSS（含各组件的 CSS Modules）按 §3.1 的像素值书写媒体查询，这不算第二份取值；仅当 JS 需要读取断点时，维护一份 TS 常量镜像，断点像素值在 `.ts/.tsx` 中只允许出现在该镜像文件。

组件别名令牌（v0.4 引入，UI-002 实现，**不计入 18 个颜色令牌契约**）：

| 语义 | CSS 变量 | 取值 |
|---|---|---|
| 主按钮表面 | `--color-primary-surface` | `#1D1D1F` |
| 主按钮表面（hover） | `--color-primary-hover` | `#000000` |
| 主按钮上的文字/图标 | `--color-on-primary` | `#FFFFFF` |
| 危险实心面上的文字/图标（v0.6） | `--color-on-danger` | `#FFFFFF` |

别名令牌只引用既有色板取值、不引入新颜色；Button 组件只能引用别名，**不得直接把 `--color-text-primary` 当表面色**（文字令牌挪作表面色会造成语义耦合），danger 变体也**不得借用 `--color-on-accent`**（蓝底白字与红底白字是两个语义，哪怕当前取值相同）。将来若配色改判或深色模式翻转，只改别名值，组件零改动。

动效令牌（v0.5 新增，对应 §6）：

| 语义 | CSS 变量 | 取值 | 取值来源 |
|---|---|---|---|
| 快速过渡（hover、按压、聚焦） | `--duration-fast` | `150ms` | 原型按钮/导航 160ms，归整到 §6 区间下界 |
| 常规过渡（抽屉位移等） | `--duration-base` | `200ms` | 原型抽屉 transform 180ms，归整到 §6 中值 |
| 缓慢过渡（浮层进退场） | `--duration-slow` | `250ms` | §6 区间上界，批次 3a 首次消费时落代码 |
| 标准缓动 | `--ease-standard` | `ease` | 原型三处过渡均为裸写 `ease` |

控件尺寸令牌（v0.5 新增，对应 §2.3）：

| 语义 | CSS 变量 | 取值 |
|---|---|---|
| 小控件高度（Button、IconButton） | `--size-control-sm` | `40px` |
| 大控件高度（Input、Select、单行 Textarea） | `--size-control-md` | `48px` |
| 移动端触控下限 | `--size-touch-min` | `44px` |

`--size-touch-min` 是语义保证值而非组件高度：tokens.css 在 `max-width: 767px` 媒体块把 `--size-control-sm` 覆盖为 `var(--size-touch-min)`（与 `--space-page-x` 的媒体覆盖同机制），组件样式自身不写媒体查询改高度。Tabs 等分段控件（原型 34px）不是独立触控目标，不预造尺寸令牌，确有需要时按同一命名规则追加。

浮层层级令牌（v0.5 新增；`--z-scrim/--z-overlay` 批次 3a 首次消费，`--z-toast` 批次 3b 首次消费）：

| 语义 | CSS 变量 | 取值 | 用途 |
|---|---|---|---|
| 遮罩层 | `--z-scrim` | `100` | Modal / Drawer 的 backdrop |
| 浮层面板 | `--z-overlay` | `200` | Modal、Drawer、ConfirmDialog 面板**共用** |
| 全局提示 | `--z-toast` | `300` | Toast（必须浮在一切浮层之上） |

层级只表达"遮罩→面板→全局提示"三档，不为单个组件开数字；原生 `select` 的弹出列表由系统绘制，不分配层级令牌。

圆角令牌（v0.7 补丸形）：

| 语义 | CSS 变量 | 取值 | 用途 |
|---|---|---:|---|
| 小圆角 | `--radius-sm` | 10px | 控件：按钮、输入框、导航项、分段控件内项 |
| 中圆角 | `--radius-md` | 14px | 卡片与表面（原型 `--radius: 16px` 归整到规范冻结值） |
| 大圆角 | `--radius-lg` | 20px | Modal、大面板 |
| 丸形 | `--radius-pill` | 999px | Badge、进度条等端帽完全圆化的元素（原型写 99px，对其 6px/24px 元素够用；令牌取 999px 保证任意高度下都是全圆端帽） |

丸形表达的是"端帽完全圆化"成语，不是第四档几何曲率，不用于普通表面。`50%`（头像、时间线圆点正圆）是几何写法而非半径档位，纪律扫描对其放行；`border-radius` 只允许引用 `--radius-*` 令牌或 `50%`/`0`/`inherit`。

状态色边框（v0.5 定值，批次 2 收编）：

| CSS 变量 | 取值 |
|---|---|
| `--color-success-border` | `rgba(45, 138, 91, 0.24)` |
| `--color-warning-border` | `rgba(183, 121, 31, 0.24)` |
| `--color-danger-border` | `rgba(192, 57, 43, 0.24)` |

推导规则：**状态色边框 = 对应语义色 24% alpha 白底快照**（与 soft 的 8% 规则并列，形成「8% 柔和底 / 24% 边框 / 100% 文字与图标」三级层次）。三色必须同一 PR 一次收编，不单独引入。收编后颜色令牌契约由 18 变为 **21**，令牌单元测试期望值在同一 PR 更新。中性 Tag 仍用次文字 + 柔和面，不新增边框令牌。

UI-002 令牌收编批次（与《开发任务清单》UI-002 四批分工对齐）：

- 批次 1：主按钮别名 3 枚、动效 3 枚（`--duration-fast/--duration-base/--ease-standard`，`--duration-slow` 批次 3a 补）、尺寸 3 枚落 tokens.css；同步把纪律验收脚本的令牌族白名单扩到 `--duration-/--ease-/--size-/--z-`，并新增「tokens.css 之外禁止出现 `ms` 时长字面量与数字 `z-index`」扫描。
- 批次 2：交付 Badge、Progress、Tabs 三个组件（Pagination 移出 UI-002，挂账 UI-005）；`--radius-pill: 999px` 与状态色边框 3 枚同 PR 落 tokens.css，颜色契约由 18 变为 21，单元测试同 PR 更新；Badge 文字使用 `--font-size-caption`（原型 11px 归整 13px，见 §2.2）；纪律脚本新增字号/圆角 px 字面量扫描（须配删除式探针）。
- 批次 3a：`--z-scrim`、`--z-overlay` 与 `--duration-slow` 随 Modal/ConfirmDialog 落 tokens.css；同 PR 建浮层内部基建（Portal 挂载、背景滚动锁、焦点陷阱、ESC 关闭、关闭后焦点归还、进退场延迟卸载），供 3b 复用，不对外导出通用浮层框架。
- 批次 3b：`--z-toast` 随 Toast 落 tokens.css（3a 无 Toast 消费者，不提前落地）；Drawer 与 Toast 复用 3a 基建，进退场采用退场延迟卸载。
- 浮层组件手写 ARIA 与进退场，不使用原生 `<dialog>`：`::backdrop` 无法引用 `--color-overlay`、进退场无法挂接动效令牌，且 Drawer 无对应原生元素，两套行为会造成分裂。
- 「需要才落代码」不等于可以先在组件里写字面量：未收编的值在消费者出现的同一个 PR 收编，禁止「先写值后补令牌」。

暂不收编（明确推后）：

- 半透明白（原型侧栏 `rgba(255,255,255,.66)`、Modal 边框 `rgba(255,255,255,.6)`）：属磨砂效果，与 §1.1 反玻璃拟态条款相关，留到 UI-003 外壳阶段决定。**v0.8 冻结处置**：批次 3a 的 Modal 不画这道白边、以无边框实现（表面白 + `--radius-lg` + `--shadow-overlay` + `--color-overlay` 遮罩已提供分离层次），不得以 `--color-border` 等既有令牌顶替伪造该视觉；是否新增磨砂边框令牌、是否补回，由 UI-003 外壳阶段对磨砂效果整体决策的同一个 PR 决定。原型 250px 左导航侧栏（含其磨砂底）同属 UI-003 外壳，不是批次 3b 的 Drawer。

使用规则：

- 令牌文件之外禁止出现 hex/rgb/hsl 字面量（含内联 style）；原型中的写死值必须先收编为本节令牌才能迁入。
- 令牌文件之外禁止出现 `ms`/`s` 时长字面量与数字 `z-index`：过渡时长、缓动、浮层层级只能引用本节动效/层级令牌，由 UI-002 批次 1 起的纪律验收脚本强制。
- 令牌文件之外禁止出现 px 数字字号（`font-size: 13px` 等）与 px 数字圆角（`border-radius: 10px` 等）：字号只能引用 `--font-size-*`，圆角只能引用 `--radius-*`；圆角放行 `50%`、`0`、`inherit`。由 UI-002 批次 2 起的纪律验收脚本强制（批次 1 组件已全部令牌化，无存量迁移）。
- `prefers-reduced-motion` 只允许在 tokens.css **单点**处理：通过一个媒体查询把三个 `--duration-*` 覆盖为 `0.01ms`；组件样式内不得写减少动效的媒体查询。
- 第一阶段只实现浅色：`:root` 声明 `color-scheme: light`。
- 深色只预留、不激活：tokens.css 保留 `html[data-theme='dark']` 占位块（值留空/注释）；仓库内任何代码不得设置 `data-theme` 属性，也不得使用 `@media (prefers-color-scheme: dark)`——系统深色用户在第一阶段必须看到已验收的浅色。
- 将来激活深色时，主题属性只挂在 `<html>` 单一节点，变量定义与覆盖选择器统一使用 `html[data-theme='dark']`，只替换变量值，引用方零改动。

已决项（v0.4，2026-09-17 产品确认）：主按钮以原型近黑底为准（见 §2.1「主操作配色」），强调色蓝不用于普通操作按钮；Button 通过上文的组件别名令牌取色，不新增基础语义色。

## 4. 组件规范

### 4.1 按钮

每组操作最多一个高强调主按钮。

- 主按钮：保存、开始、确认。
- 次按钮：编辑、安排、查看详情。
- 低强调按钮：取消、稍后处理、跳过。
- 危险按钮：删除、彻底清除，必须二次确认。

主按钮外观为近黑实心白字（`#1D1D1F` / hover `#000000`，v0.4 定稿，取值与理由见 §2.1、别名令牌见 §2.4）；强调色蓝不用于操作按钮。

按钮文案使用动词，不使用“确定”作为所有场景的默认词。

### 4.2 任务卡片

任务卡片至少展示：

- 任务名称。
- 时间或预计时长。
- 所属领域/目标，可选。
- 当前状态。
- 一个主要操作。

不要在列表卡片中同时展示所有备注、历史、统计和 AI 信息。

### 4.3 时间线块

- 显示开始时间、名称、预计时长。
- 固定事项、任务、例程使用不同图标或标签辅助区分。
- 当前时间线使用一条清晰但克制的强调线。
- 冲突使用图标 + 文案 + 轻量背景，不只使用红色。

### 4.4 表单

- 先展示最少必填字段。
- 高级字段折叠在“更多设置”中。
- 金额输入默认聚焦金额，不要求先选分类。
- 错误信息靠近字段，说明如何修正。
- 保存成功给出非阻塞反馈，避免打断用户下一步。

### 4.5 抽屉和弹窗

- 详情编辑优先使用侧边抽屉。
- 删除、导入、账户删除使用居中确认弹窗。
- AI 结果使用“草稿面板”，展示原文、建议结果、编辑和取消。
- 弹窗不能包含完整复杂流程；复杂流程改用独立页面。

浮层组件形态（v0.8 冻结形态、v0.9 补实现级决策，UI-002 批次 3a/3b 实现；视觉取值只引用 §2.4 令牌，不新写颜色/时长/层级）：

- **Modal（居中模态，批次 3a）**：原型 `.modal-backdrop/.modal` 为据——遮罩 `--color-overlay`、面板宽 `min(480px, 100%)`、`--radius-lg`、表面色底加 `--shadow-overlay`；**不画原型那道 `rgba(255,255,255,.6)` 磨砂白边**（处置见 §2.4 暂不收编）。行为：`role="dialog"` + `aria-modal="true"` + `aria-labelledby`；ESC 与点击遮罩关闭、X 关闭；打开时锁定背景滚动、焦点进入面板并在面板内循环，关闭后焦点归还触发元素；进退场用 `--duration-slow`。
- **ConfirmDialog（确认弹窗，批次 3a）**：Modal 的特化，不另建浮层机制；`role="alertdialog"`，正文经 `aria-describedby` 关联；危险操作（删除、账户删除等）的初始焦点落在「取消」而非确认按钮，防误触；ESC/遮罩关闭语义等同取消。
- **Drawer（详情编辑抽屉，批次 3b）**：**桌面端右侧滑入**，宽 `min(440px, 100vw)`，遮罩、滚动锁、焦点管理与 Modal 同机制；位移用 `--duration-base`（原型抽屉 180ms 归整值），不用 `--duration-slow`；**≤767px 全屏呈现**（移动端在「底部抽屉或全屏页面」中冻结为全屏，避免编辑表单遇虚拟键盘拥挤）。本组件不做左/右/底部方向引擎：原型 250px 左滑物是**移动端导航 sidebar**，连同磨砂侧栏归 UI-003 外壳，届时若复用再补方向参数。**面板结构（v0.9 冻结）**：容器 fixed 右贴边、`height: 100dvh`（回退 100vh），grid 三行 `auto 1fr auto`，表面色底、**圆角 0**（贴视口边缘的锚定面板；0 属纪律扫描放行值，不产生新令牌）；**header**（标题 + 关闭 IconButton，下划 `1px var(--color-border)`，不滚动）、**body**（`overflow-y: auto`，编辑表单唯一落点）、**footer 可选**（上划线 + 右对齐按钮组，钉底使长表单滚动时操作可达）；≤767px 全屏同构；props 与 Modal 镜像（`title/footer/initialFocusSelector/closable`），初始焦点面板本身。
- **Toast（全局非阻塞反馈，批次 3b）**：原型无此形态，按本节冻结实现——底部居中堆叠、同时最多 3 条；表面色底 + `--radius-md` + `--shadow-overlay`，层级 `--z-toast`（须浮于一切浮层之上，挂 body 级容器）；普通/成功态 `role="status"`（等价 `aria-live="polite"`，对应 §7），错误态 `role="alert"`；不夺走页面焦点。自动关闭时长为组件内命名常量、不做 CSS 令牌：普通 5s、带操作按钮 8s、**错误态常驻不自动关闭**（NFR-REL-002：失败必须明确提示）。组件只提供操作槽（如「撤销」），不内置撤销业务逻辑；归档/删除/延期等撤销随真实消费者接线（§6）。进退场与 Drawer 同为退场延迟卸载，进退场时长用 `--duration-fast`（Toast 非模态、不锁背景，反馈应快于模态浮层的 `--duration-slow`）。**公共 API、队列与变体（v0.9 冻结）**：API 为 **`<ToastProvider>` + `useToast()`**——provider 作为客户端 island 在根布局包住 children，`toast.show/success/error(message, options?)` 返回 id，另可 `toast.dismiss(id)`；不做模块级命令式单例（当前不存在非 React 调用方，未来统一请求层需要时再在 provider 下加 emitter 适配）。堆叠：新条在**最底部**（拇指最近）、旧条向上顶；满 3 条时**淘汰最老的自动关闭条，错误常驻条豁免淘汰**——若槽位均被错误条占用，新普通/成功条直接丢弃；**悬停或聚焦某条暂停其计时**，移出后重新计时；每条带手动关闭 ×。状态变体只以前导语义图标区分：普通无图标、成功内联 SVG 对勾取 `--color-success`、错误内联 SVG 警示取 `--color-danger`（图标自包含、`fill: currentColor`，项目不引入图标库）；正文文字一律 `--color-text-primary`，**背景一律 surface**（不铺 soft 底），不做 warning 变体；操作槽文字用 `--color-accent`。每条自身带 role，外层容器不再套 aria-live，避免双重播报。

### 4.6 页面状态（v0.11 冻结，UI-002 批次 4 实现）

EmptyState / LoadingState / ErrorState 是占满内容区的页面/区块级状态，与 Toast（瞬时非阻塞反馈）、Button 的 `loading`（控件级进行态）分工，互不替代。共同解剖：纵列居中，`title` + `description` 两段文字；操作一律以 **ReactNode 槽**传入真实 Button（不接收 `{label,onClick}` 配置对象，以保留 Button 的 variant/loading 等全部能力）；**零新增令牌**，颜色/字号/圆角/间距只引用 §2.4 既有令牌。

- **EmptyState（空状态）**：原型 `.empty-state` 为据——表面底 + `1px dashed var(--color-border)` 虚线框 + `--radius-md`（原型 16px 就近归整 14px）+ 纵 `--space-12`/横 `--space-6` 内边距（原型 56px 就近归整 48px）+ 居中；标题用 `--font-size-body`/medium/`--color-text-primary`，描述用 `--color-text-secondary`；**不加图标**（原型无此形态，无消费者不预造）。§1「空状态提供具体下一步，不使用泛化文案」由描述文案或操作承担：`action`、`secondaryAction` 两个操作槽均可选。
- **LoadingState（加载状态）**：页面/区块首次加载用**静态骨架**，不用 spinner，也不用闪烁、发光、呼吸等循环动画（§6：首次加载不使用无意义的循环动画）。容器 `role="status"` + `aria-busy="true"`，配视觉隐藏的加载说明（等价 `aria-live="polite"`，§7）。同模块导出 **Skeleton** 支撑原语（`--color-surface-soft` 底 + `--radius-sm`，宽高由调用方给定），由调用方用间距令牌组合标题/段落/列表轮廓，**不做 `shape` 预设引擎**。保存、同步、AI 处理的进行态不归本组件（Button loading、Progress、Toast 各有其位）。
- **ErrorState（阻塞式错误状态）**：无衬底边框（虚线框是「这里还没有东西」的空态专属语言）、居中、宽 `min(480px, 100%)` 与 Modal 同族；一枚 `currentColor` 内联警示图标取 `--color-danger`，是组件内**唯一红色**——标题仍用 `--color-text-primary`、描述 `--color-text-secondary`，不做整面红（§1 克制基调，并为删除场景保留 danger 的分量）；容器 `role="alert"`，插入即播报。主操作槽传重试按钮，用近黑 **primary** 变体（重试是肯定动作，danger 只留给破坏性确认），次操作槽可选。

## 5. 页面规范

### 今日页

- 首屏优先显示当前行动和时间线。
- 顶部最多一个主 CTA：“添加”。
- 今日摘要放在时间线下方，不抢当前行动注意力。
- 未安排任务使用轻量列表，不采用大面积警告颜色。

### 收件箱

- 输入框在首屏。
- 任务列表按最近添加排序。
- 每行只保留安排、关联、归档三个高频动作。

### 目标

- 目标卡片展示结果描述、行动数量和最近进展。
- 不把进度条做成唯一的成功反馈。
- 目标详情页必须能直接新增今日行动。

### 开销

- 快速记账按钮固定在页面明显位置。
- 记录列表默认按时间倒序。
- 金额使用等宽数字或 tabular figures，便于扫描。
- 分类和目标关联采用可搜索选择，但常用项优先。

### 复盘

- 复盘页面按“看到事实 → 理解偏差 → 做出调整”排序。
- 每个洞察后放一个就地操作。
- AI 摘要必须标注“AI 建议”，并支持编辑和取消。

## 6. 交互和动效

- 常规状态过渡 150–250ms，时长与缓动只允许引用 §2.4 动效令牌，禁止组件内写时长字面量。
- 首次加载不使用无意义的循环动画。
- 保存、同步、AI 处理使用明确的进行中状态。
- 支持 `prefers-reduced-motion`，减少动效：降级在 tokens.css 单点完成（§2.4 使用规则），组件不写 `prefers-reduced-motion` 媒体查询。
- 拖拽操作必须有键盘和点击替代方案。
- 操作成功后提供撤销，尤其是归档、删除和延期。

## 7. 无障碍和兼容性

- 使用语义化 HTML 和原生 button、input、select。
- 键盘可完成创建、编辑、完成、延期和关闭浮层。
- 焦点状态清晰可见。
- 表单字段有 label，错误使用 `role="alert"`。
- 动态保存和同步状态使用 `aria-live="polite"`。
- 不把 hover 作为关键操作唯一入口。
- 支持 Chrome、Edge、Safari、Firefox 目标版本。

## 8. 设计交付规则

每个页面交付必须包含：

1. 默认状态。
2. 空状态。
3. 加载状态。
4. 错误状态。
5. 无权限/未登录状态。
6. 移动窄屏状态。
7. 键盘和触控替代交互。
8. 文案和数据格式说明。
