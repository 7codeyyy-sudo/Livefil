# Livefil UI 页面规范

> 版本：v0.5  
> 设计方向：高级简约、浅色优先、PC Web 先行、移动端预留  
> 日期：2026-09-17  
> 变更：v0.2 新增 §2.4 设计令牌的 CSS 命名与深色预留约定（对应 T-002 样式方案确认、UI-001）；v0.3 颜色令牌补齐为基础 9 + 派生/辅助 9（新增 surface-soft、text-placeholder、focus-ring、overlay 与 warning/danger-soft 权威值），新增 2 个阴影令牌、soft 推导规则、暂不收编项；v0.4 定稿主按钮配色为近黑实心（原待决项关闭），主强调色语义收窄为状态/进度/焦点，新增组件别名令牌约定（§2.4），§4.1 同步；v0.5 为 UI-002 新增动效、控件尺寸、浮层层级三族令牌与字面量纪律，状态色边框三色定值（颜色契约批次 2 起 18→21），明确 UI-002 令牌收编批次，§6 增加动效令牌指针

## 1. 视觉关键词

克制、清晰、安静、可靠、有呼吸感。

参考苹果产品的设计原则：留白、层次、内容聚焦、低干扰动效和高质量排版；不复制苹果官网的品牌标志、插画、页面素材或具体布局。

## 1.1 减少 AI 味规范

产品应该像一个经过长期打磨的生活工具，而不是 AI 生成的概念展示页。所有 AI 生成的页面和组件都必须通过以下检查。

### 明确避免

- 不使用大面积蓝紫渐变、霓虹发光、玻璃拟态和科技网格作为默认视觉。
- 不使用机器人头像、魔法棒、星星闪光和“AI 魔法”等装饰作为主要视觉语言。
- 不把首页做成聊天窗口或 AI 对话首页。
- 不用大量圆角卡片、标签、徽章和 KPI 数字填满页面。
- 不使用没有真实业务作用的仪表盘、环形图和趋势图。
- 不把所有操作都包装成“智能”“魔法”“自动化”。
- 不使用过于夸张的渐入、漂浮、脉冲和持续循环动效。
- 不使用没有内容依据的插画、人物照片或 AI 生成装饰图。
- 不让 AI 建议使用比用户任务更强的视觉层级。

### 推荐使用

- 中性色为主，一个稳定的品牌强调色为辅。
- 用排版、间距和真实内容建立层次，而不是靠阴影、渐变和装饰。
- 让用户的任务、时间、金额和下一步行动成为视觉主体。
- 使用简洁的线性图标和明确文字，不依赖图标猜含义。
- 让页面保留适度空白，不为了“看起来丰富”添加无关模块。
- AI 建议使用普通的建议区、草稿区或上下文操作，不使用发光按钮。
- 重要操作使用直接动词，例如“拆分任务”“安排时间”“保存建议”。
- 空状态提供具体下一步，不使用泛化的“开启你的 AI 之旅”。

### AI 功能的视觉层级

AI 必须是产品中的辅助能力，不是品牌主角：

1. 用户手动操作始终可用。
2. AI 入口放在任务、排程和复盘的上下文中。
3. AI 结果明确标记为“建议”或“草稿”。
4. AI 结果必须可编辑、取消和撤销。
5. AI 加载状态使用普通的进度反馈，不使用持续闪烁或发光动画。

### 去 AI 味验收清单

- [ ] 去掉无业务作用的渐变、发光和装饰图。
- [ ] 页面首屏能看见真实任务或下一步行动。
- [ ] 页面不是卡片和数字的堆叠。
- [ ] AI 不是首页唯一入口。
- [ ] AI 建议的视觉权重低于用户确认后的正式数据。
- [ ] 所有图标和颜色都有明确语义。
- [ ] 去掉无法解释的动画和“科技感”装饰。
- [ ] 文案像生活工具，而不是营销型 AI 产品。

## 2. 设计令牌

### 2.1 色彩

第一阶段使用浅色主题：

| 语义 | 建议值 | 用途 |
|---|---|---|
| 页面背景 | `#F7F7F5` | 页面整体背景 |
| 主表面 | `#FFFFFF` | 卡片、抽屉、输入区域 |
| 主文字 | `#1D1D1F` | 标题和重要内容 |
| 次文字 | `#6E6E73` | 辅助说明和时间 |
| 边界 | `#E5E5E2` | 分隔线和输入框 |
| 主强调色 | `#1769E0` | 当前状态、进度、焦点、品牌点缀 |
| 成功 | `#2D8A5B` | 完成、同步成功 |
| 警告 | `#B7791F` | 超载、冲突、待处理 |
| 危险 | `#C0392B` | 删除、错误、失败 |

颜色不能成为唯一语义载体；完成、延期和冲突同时使用文字、图标或状态标签。

**主操作配色（v0.4 定稿）**：保存、开始、确认等高强调主按钮使用**近黑实心**——底色 `#1D1D1F`、hover `#000000`、白字，**不使用强调色蓝**。原型的黑按钮已经过整体视觉验收；蓝色在本系统中专指「此刻活着的状态」（当前时间线、进度填充、焦点环），与「动作」分离，避免同屏蓝色按钮与蓝色状态互相抢夺语义，也把全页饱和色面积压到最低（§1「中性色为主，一个强调色为辅」）。

### 2.2 字体

```css
font-family: -apple-system, BlinkMacSystemFont, "Segoe UI",
  "PingFang SC", "Microsoft YaHei", sans-serif;
```

| 层级 | 字号 | 字重 | 行高 |
|---|---:|---:|---:|
| 页面标题 | 28–32px | 500 | 1.25 |
| 区域标题 | 18–20px | 500 | 1.35 |
| 正文 | 14–16px | 400 | 1.5 |
| 辅助文字 | 12–13px | 400 | 1.45 |
| 数字摘要 | 24–32px | 500 | 1.1 |

第一阶段仅使用 400 和 500 两种字重，避免视觉噪声。

### 2.3 间距和圆角

- 基础间距单位：4px。
- 页面内边距：桌面 32px，平板 24px，手机 16px。
- 内容最大宽度：1200px。
- 常用圆角：10px、14px、20px。
- 主要按钮触控高度：至少 40px；移动端主要触控目标建议 44px（控件高度令牌化，取值与移动端覆盖机制见 §2.4）。
- 阴影极少使用，只用于抽屉、浮层和主操作反馈。

### 2.4 设计令牌的 CSS 命名与使用约定

本节把 §2.1–§2.3 的设计令牌落到 CSS 形态（对应 T-002：原生 CSS 自定义属性 + CSS Modules）。令牌唯一定义在 `src/shared/ui/styles/tokens.css`，由应用根布局唯一导入；组件使用 CSS Modules 引用变量，不直接写字面量。

颜色令牌当前共 18 个：9 个基础语义色（对应 §2.1，逐行给出权威取值）+ 9 个派生/辅助色。UI-002 批次 2 收编 3 个状态色边框后扩为 21 个（见下文「状态色边框」）。

基础语义色（9 个）：

| 语义 | CSS 变量 | 浅色取值 |
|---|---|---|
| 页面背景 | `--color-bg-page` | `#F7F7F5` |
| 主表面 | `--color-surface` | `#FFFFFF` |
| 主文字 | `--color-text-primary` | `#1D1D1F` |
| 次文字 | `--color-text-secondary` | `#6E6E73` |
| 边界 | `--color-border` | `#E5E5E2` |
| 主强调色 | `--color-accent` | `#1769E0` |
| 成功 | `--color-success` | `#2D8A5B` |
| 警告 | `--color-warning` | `#B7791F` |
| 危险 | `--color-danger` | `#C0392B` |

派生/辅助色（9 个）：

| 语义 | CSS 变量 | 浅色取值 | 取值来源 |
|---|---|---|---|
| 柔和面（悬停/选中、标签、分段控件、进度轨道） | `--color-surface-soft` | `#F0F0ED` | 原型 `--surface-soft`，6 处使用 |
| 占位文字 | `--color-text-placeholder` | `#A2A2A7` | 原型输入框 placeholder |
| 强调色上的文字/图标 | `--color-on-accent` | `#FFFFFF` | 原型头像文字 `#fff`（主按钮白字见 v0.4 别名 `--color-on-primary`） |
| 强调色柔和底（选中态、浅底容器） | `--color-accent-soft` | `#EAF1FF` | 原型 `--blue-soft` |
| 键盘焦点环 | `--color-focus-ring` | `rgba(23, 105, 224, 0.28)` | 原型 `:focus-visible`（§7 要求焦点可见） |
| 弹层遮罩 | `--color-overlay` | `rgba(29, 29, 31, 0.28)` | 原型 modal-backdrop |
| 成功柔和底 | `--color-success-soft` | `rgba(45, 138, 91, 0.08)` | 原型完成态底色 |
| 警告柔和底 | `--color-warning-soft` | `rgba(183, 121, 31, 0.08)` | 按 soft 推导规则生成 |
| 危险柔和底 | `--color-danger-soft` | `rgba(192, 57, 43, 0.08)` | 按 soft 推导规则生成 |

`*-soft` 推导规则：**状态色柔和底 = 对应语义色在白底上按 8% alpha 叠加的快照**（`rgba(<语义色 RGB>, 0.08)`）。accent-soft 保留原型已验收的定值 `#EAF1FF`，不强行改为纯 8%。焦点环的 3px 宽度与 2px offset 是几何不是颜色，写在 base/组件样式中，不做颜色令牌。

阴影令牌（2 个，只允许这两处阴影）：

| 语义 | CSS 变量 | 取值 |
|---|---|---|
| 弹层阴影（Modal、Drawer） | `--shadow-overlay` | `0 16px 44px rgba(29, 29, 31, 0.10)` |
| 抬升阴影（Tabs 等激活项、主操作反馈） | `--shadow-raised` | `0 1px 4px rgba(29, 29, 31, 0.06)` |

其他令牌族：`--font-*`（字体族、字号、字重、行高，取值见 §2.2）、`--space-*`（4px 倍数）、`--radius-*`（10/14/20px）。断点不做成 CSS 变量（变量无法用于 `@media` 条件）：CSS（含各组件的 CSS Modules）按 §3.1 的像素值书写媒体查询，这不算第二份取值；仅当 JS 需要读取断点时，维护一份 TS 常量镜像，断点像素值在 `.ts/.tsx` 中只允许出现在该镜像文件。

组件别名令牌（v0.4 引入，UI-002 实现，**不计入 18 个颜色令牌契约**）：

| 语义 | CSS 变量 | 取值 |
|---|---|---|
| 主按钮表面 | `--color-primary-surface` | `#1D1D1F` |
| 主按钮表面（hover） | `--color-primary-hover` | `#000000` |
| 主按钮上的文字/图标 | `--color-on-primary` | `#FFFFFF` |

别名令牌只引用既有色板取值、不引入新颜色；Button 组件只能引用别名，**不得直接把 `--color-text-primary` 当表面色**（文字令牌挪作表面色会造成语义耦合）。将来若配色改判或深色模式翻转，只改别名值，组件零改动。

动效令牌（v0.5 新增，对应 §6）：

| 语义 | CSS 变量 | 取值 | 取值来源 |
|---|---|---|---|
| 快速过渡（hover、按压、聚焦） | `--duration-fast` | `150ms` | 原型按钮/导航 160ms，归整到 §6 区间下界 |
| 常规过渡（抽屉位移等） | `--duration-base` | `200ms` | 原型抽屉 transform 180ms，归整到 §6 中值 |
| 缓慢过渡（浮层进退场） | `--duration-slow` | `250ms` | §6 区间上界，批次 3 首次消费时落代码 |
| 标准缓动 | `--ease-standard` | `ease` | 原型三处过渡均为裸写 `ease` |

控件尺寸令牌（v0.5 新增，对应 §2.3）：

| 语义 | CSS 变量 | 取值 |
|---|---|---|
| 小控件高度（Button、IconButton） | `--size-control-sm` | `40px` |
| 大控件高度（Input、Select、单行 Textarea） | `--size-control-md` | `48px` |
| 移动端触控下限 | `--size-touch-min` | `44px` |

`--size-touch-min` 是语义保证值而非组件高度：tokens.css 在 `max-width: 767px` 媒体块把 `--size-control-sm` 覆盖为 `var(--size-touch-min)`（与 `--space-page-x` 的媒体覆盖同机制），组件样式自身不写媒体查询改高度。Tabs 等分段控件（原型 34px）不是独立触控目标，不预造尺寸令牌，确有需要时按同一命名规则追加。

浮层层级令牌（v0.5 新增，批次 3 首次消费时落代码）：

| 语义 | CSS 变量 | 取值 | 用途 |
|---|---|---|---|
| 遮罩层 | `--z-scrim` | `100` | Modal / Drawer 的 backdrop |
| 浮层面板 | `--z-overlay` | `200` | Modal、Drawer、ConfirmDialog 面板**共用** |
| 全局提示 | `--z-toast` | `300` | Toast（必须浮在一切浮层之上） |

层级只表达"遮罩→面板→全局提示"三档，不为单个组件开数字；原生 `select` 的弹出列表由系统绘制，不分配层级令牌。

状态色边框（v0.5 定值，批次 2 收编）：

| CSS 变量 | 取值 |
|---|---|
| `--color-success-border` | `rgba(45, 138, 91, 0.24)` |
| `--color-warning-border` | `rgba(183, 121, 31, 0.24)` |
| `--color-danger-border` | `rgba(192, 57, 43, 0.24)` |

推导规则：**状态色边框 = 对应语义色 24% alpha 白底快照**（与 soft 的 8% 规则并列，形成「8% 柔和底 / 24% 边框 / 100% 文字与图标」三级层次）。三色必须同一 PR 一次收编，不单独引入。收编后颜色令牌契约由 18 变为 **21**，令牌单元测试期望值在同一 PR 更新。中性 Tag 仍用次文字 + 柔和面，不新增边框令牌。

UI-002 令牌收编批次（与《开发任务清单》UI-002 四批分工对齐）：

- 批次 1：主按钮别名 3 枚、动效 3 枚（`--duration-fast/--duration-base/--ease-standard`，`--duration-slow` 批次 3 补）、尺寸 3 枚落 tokens.css；同步把纪律验收脚本的令牌族白名单扩到 `--duration-/--ease-/--size-/--z-`，并新增「tokens.css 之外禁止出现 `ms` 时长字面量与数字 `z-index`」扫描。
- 批次 2：状态色边框 3 枚落 tokens.css，颜色契约由 18 变为 21，单元测试同 PR 更新。
- 批次 3：`--z-scrim`、`--z-overlay`、`--z-toast` 与 `--duration-slow` 随首个消费者落 tokens.css。
- 「需要才落代码」不等于可以先在组件里写字面量：未收编的值在消费者出现的同一个 PR 收编，禁止「先写值后补令牌」。

暂不收编（明确推后）：

- 半透明白（原型侧栏 `rgba(255,255,255,.66)`、Modal 边框 `rgba(255,255,255,.6)`）：属磨砂效果，与 §1.1 反玻璃拟态条款相关，留到 UI-003 外壳阶段决定。

使用规则：

- 令牌文件之外禁止出现 hex/rgb/hsl 字面量（含内联 style）；原型中的写死值必须先收编为本节令牌才能迁入。
- 令牌文件之外禁止出现 `ms`/`s` 时长字面量与数字 `z-index`：过渡时长、缓动、浮层层级只能引用本节动效/层级令牌，由 UI-002 批次 1 起的纪律验收脚本强制。
- `prefers-reduced-motion` 只允许在 tokens.css **单点**处理：通过一个媒体查询把三个 `--duration-*` 覆盖为 `0.01ms`；组件样式内不得写减少动效的媒体查询。
- 第一阶段只实现浅色：`:root` 声明 `color-scheme: light`。
- 深色只预留、不激活：tokens.css 保留 `html[data-theme='dark']` 占位块（值留空/注释）；仓库内任何代码不得设置 `data-theme` 属性，也不得使用 `@media (prefers-color-scheme: dark)`——系统深色用户在第一阶段必须看到已验收的浅色。
- 将来激活深色时，主题属性只挂在 `<html>` 单一节点，变量定义与覆盖选择器统一使用 `html[data-theme='dark']`，只替换变量值，引用方零改动。

已决项（v0.4，2026-09-17 产品确认）：主按钮以原型近黑底为准（见 §2.1「主操作配色」），强调色蓝不用于普通操作按钮；Button 通过上文的组件别名令牌取色，不新增基础语义色。

## 3. 页面布局

### 3.1 断点

| 断点 | 用途 |
|---|---|
| 320–767px | 手机竖屏，单列和底部导航 |
| 768–1023px | 平板/窄桌面，折叠侧栏 |
| 1024–1439px | 标准桌面，侧栏 + 主内容 |
| 1440px 以上 | 宽桌面，内容最大宽度限制 |

### 3.2 PC Web 外壳

- 左侧导航宽度 224–248px。
- 主内容区最大宽度 1200px。
- 顶部工具栏只放当前页必要操作。
- 全局“快速添加”在顶部和键盘快捷键中可达。
- 重要弹层从右侧出现，避免遮挡全部上下文。

### 3.3 移动端外壳预留

- 左侧导航切换为底部五项导航或顶部菜单。
- 详情侧栏切换为底部抽屉。
- 时间线横向密度降低，允许按时间段折叠。
- 统计图表优先改成文字摘要和纵向列表。

## 4. 组件规范

### 4.1 按钮

每组操作最多一个高强调主按钮。

- 主按钮：保存、开始、确认。
- 次按钮：编辑、安排、查看详情。
- 低强调按钮：取消、稍后处理、跳过。
- 危险按钮：删除、彻底清除，必须二次确认。

主按钮外观为近黑实心白字（`#1D1D1F` / hover `#000000`，v0.4 定稿，取值与理由见 §2.1、别名令牌见 §2.4）；强调色蓝不用于操作按钮。

按钮文案使用动词，不使用“确定”作为所有场景的默认词。

### 4.2 任务卡片

任务卡片至少展示：

- 任务名称。
- 时间或预计时长。
- 所属领域/目标，可选。
- 当前状态。
- 一个主要操作。

不要在列表卡片中同时展示所有备注、历史、统计和 AI 信息。

### 4.3 时间线块

- 显示开始时间、名称、预计时长。
- 固定事项、任务、例程使用不同图标或标签辅助区分。
- 当前时间线使用一条清晰但克制的强调线。
- 冲突使用图标 + 文案 + 轻量背景，不只使用红色。

### 4.4 表单

- 先展示最少必填字段。
- 高级字段折叠在“更多设置”中。
- 金额输入默认聚焦金额，不要求先选分类。
- 错误信息靠近字段，说明如何修正。
- 保存成功给出非阻塞反馈，避免打断用户下一步。

### 4.5 抽屉和弹窗

- 详情编辑优先使用侧边抽屉。
- 删除、导入、账户删除使用居中确认弹窗。
- AI 结果使用“草稿面板”，展示原文、建议结果、编辑和取消。
- 弹窗不能包含完整复杂流程；复杂流程改用独立页面。

## 5. 页面规范

### 今日页

- 首屏优先显示当前行动和时间线。
- 顶部最多一个主 CTA：“添加”。
- 今日摘要放在时间线下方，不抢当前行动注意力。
- 未安排任务使用轻量列表，不采用大面积警告颜色。

### 收件箱

- 输入框在首屏。
- 任务列表按最近添加排序。
- 每行只保留安排、关联、归档三个高频动作。

### 目标

- 目标卡片展示结果描述、行动数量和最近进展。
- 不把进度条做成唯一的成功反馈。
- 目标详情页必须能直接新增今日行动。

### 开销

- 快速记账按钮固定在页面明显位置。
- 记录列表默认按时间倒序。
- 金额使用等宽数字或 tabular figures，便于扫描。
- 分类和目标关联采用可搜索选择，但常用项优先。

### 复盘

- 复盘页面按“看到事实 → 理解偏差 → 做出调整”排序。
- 每个洞察后放一个就地操作。
- AI 摘要必须标注“AI 建议”，并支持编辑和取消。

## 6. 交互和动效

- 常规状态过渡 150–250ms，时长与缓动只允许引用 §2.4 动效令牌，禁止组件内写时长字面量。
- 首次加载不使用无意义的循环动画。
- 保存、同步、AI 处理使用明确的进行中状态。
- 支持 `prefers-reduced-motion`，减少动效：降级在 tokens.css 单点完成（§2.4 使用规则），组件不写 `prefers-reduced-motion` 媒体查询。
- 拖拽操作必须有键盘和点击替代方案。
- 操作成功后提供撤销，尤其是归档、删除和延期。

## 7. 无障碍和兼容性

- 使用语义化 HTML 和原生 button、input、select。
- 键盘可完成创建、编辑、完成、延期和关闭浮层。
- 焦点状态清晰可见。
- 表单字段有 label，错误使用 `role="alert"`。
- 动态保存和同步状态使用 `aria-live="polite"`。
- 不把 hover 作为关键操作唯一入口。
- 支持 Chrome、Edge、Safari、Firefox 目标版本。

## 8. 设计交付规则

每个页面交付必须包含：

1. 默认状态。
2. 空状态。
3. 加载状态。
4. 错误状态。
5. 无权限/未登录状态。
6. 移动窄屏状态。
7. 键盘和触控替代交互。
8. 文案和数据格式说明。
