# Livefil API 接口文档

> 版本：v0.1  
> 协议：HTTPS + REST/JSON  
> API 前缀：`/api/v1`  
> 日期：2026-09-15

## 1. 通用约定

### 1.1 请求头

```http
Content-Type: application/json
Accept: application/json
Authorization: Bearer <access-token>
X-Request-Id: <client-request-id>
Idempotency-Key: <unique-key-for-write-request>
```

`Authorization` 在本地模式可省略；云端模式必须由服务端识别用户。

写操作建议携带 `Idempotency-Key`。客户端重试同一业务操作时必须复用相同 key。

### 1.2 成功响应

```json
{
  "data": {},
  "meta": {
    "requestId": "req_123",
    "serverTime": "2026-09-15T10:00:00Z"
  }
}
```

### 1.3 分页响应

```json
{
  "data": [],
  "meta": {
    "requestId": "req_123",
    "nextCursor": "cursor_value",
    "hasMore": true
  }
}
```

### 1.4 错误响应

```json
{
  "error": {
    "code": "VALIDATION_ERROR",
    "message": "任务标题不能为空",
    "fields": {
      "title": "required"
    },
    "requestId": "req_123"
  }
}
```

错误码：

| HTTP | code | 说明 |
|---:|---|---|
| 400 | `VALIDATION_ERROR` | 输入不合法 |
| 401 | `AUTHENTICATION_REQUIRED` | 未登录或令牌失效 |
| 403 | `FORBIDDEN` | 无权访问 |
| 404 | `NOT_FOUND` | 资源不存在或不属于当前用户 |
| 409 | `CONFLICT` | 版本冲突或重复操作 |
| 409 | `IDEMPOTENCY_REPLAY` | 操作已经处理 |
| 429 | `RATE_LIMITED` | 超过限流或 AI 配额 |
| 502 | `DEPENDENCY_UNAVAILABLE` | 外部服务不可用 |
| 504 | `DEPENDENCY_TIMEOUT` | 外部服务超时 |
| 500 | `INTERNAL_ERROR` | 未预期错误 |

## 2. 认证与用户

> 实现状态（2026-09-20）：Phase 2 只交付**本地单用户模式**；邀请制云端账号挂账（决策 T-006）。

### POST `/auth/local/session`

创建（幂等确保）本地模式会话。**无需请求体、无需凭证**：服务端在单事务内确保唯一本地用户与默认生活领域存在，经 `Set-Cookie` 下发签名会话。

响应：

```json
{
  "data": {
    "mode": "local",
    "userId": "uuid"
  }
}
```

`Set-Cookie`：HttpOnly、SameSite=Lax（生产环境 Secure）、Path=/。重复调用幂等，不产生第二个用户。

### POST `/auth/cloud/request-link` 〔挂账·本批未实现〕

邀请账号模式的登录链接/验证码端点。本批不实现（请求落入 FND-005 结构化 404）；认证方式（邮箱密码或魔法链接二选一）待云端批次拍板，不接社交登录。

### GET `/me`

获取当前用户设置与数据模式。本地模式下无有效会话 Cookie 时，经 EnsureLocalSession 自动初始化——响应 200 并 `Set-Cookie`，**不返回 401**。

响应 `data`：

```json
{
  "id": "uuid",
  "mode": "local",
  "displayName": null,
  "locale": "zh-CN",
  "timezone": "Asia/Shanghai",
  "currencyCode": "CNY",
  "weekStartsOn": 1,
  "defaultTaskDurationMinutes": 30,
  "defaultBufferMinutes": 10,
  "aiEnabled": false,
  "aiDataConsent": false,
  "reminderEnabled": true,
  "quietHoursStart": "22:00",
  "quietHoursEnd": "08:00",
  "version": "3"
}
```

### PATCH `/me`

更新设置；字段同 GET（除 id、mode），均可选。经 Zod 校验，**单事务整体成功或失败，无部分更新**。

跨字段约束：`aiEnabled=true` 要求 `aiDataConsent=true`。

成功返回更新后的完整设置（同 GET data）与自增 `version`。

错误：

- 422 `VALIDATION_ERROR`：locale/timezone 不受支持、currencyCode 非 3 字母、weekStartsOn 越界（0–6）、时长/缓冲为负、安静时段非法、AI 同意约束不满足。
- 409 `CONFLICT`：`version` 与当前不符。

## 3. 生活领域

### GET `/life-areas`

返回当前用户的生活领域，按 `sortOrder` 升序。

查询参数：

- `includeArchived`：默认 `false` 仅未归档；`true` 时含已归档（供「显示已归档」查看）。

### POST `/life-areas`

```json
{
  "name": "健康",
  "colorKey": "green"
}
```

校验：名称必填、≤60 字符；colorKey 必须是分类色集合之一——`blue` | `green` | `amber` | `violet` | `teal` | `rose`（定义见 UI 规范 §2.1，该枚举为契约），缺省取 `blue`；不存前端色值。新领域 sortOrder 取末位。

错误：422 `VALIDATION_ERROR`；409 `CONFLICT`（同用户未归档同名）。

### PATCH `/life-areas/{lifeAreaId}`

更新名称、colorKey（枚举同 POST）或归档状态（字段均可选）：

```json
{ "name": "身心健康", "isArchived": false }
```

归档（`isArchived:true`）只置标志位、不删行，历史关联保持可解析；重复归档返回 422。

### POST `/life-areas/reorder`

批量排序（单事务，避免多次 PATCH 产生中间错乱状态）：

```json
{ "orderedIds": ["uuid-1", "uuid-2", "uuid-3"] }
```

`orderedIds` 必须恰好等于当前用户全部未归档领域集合（多、少、含他人/已归档 id → 422）；成功后按列表顺序重排 sortOrder。

### DELETE `/life-areas/{lifeAreaId}`

**语义＝归档**（置 is_archived），不删除历史任务、目标和开销关联；非本人或不存在的 id 返回 404（不泄露存在性）。

## 4. 任务和收件箱

### GET `/tasks`

查询参数：

- `status`
- `from`
- `to`
- `lifeAreaId`
- `goalId`
- `cursor`
- `limit`

### POST `/tasks`

```json
{
  "title": "整理项目资料",
  "lifeAreaId": "uuid",
  "estimatedMinutes": 45,
  "minimumVersion": "只整理 10 分钟",
  "status": "inbox"
}
```

### GET `/tasks/{taskId}`

返回任务、关联目标、时间块摘要和最近执行记录。

### PATCH `/tasks/{taskId}`

必须携带 `version`，服务端执行乐观并发校验。

```json
{
  "title": "整理项目资料和链接",
  "version": 3
}
```

### POST `/tasks/{taskId}/status`

```json
{
  "status": "deferred",
  "reasonCode": "NO_ENERGY",
  "note": "今天临时加班"
}
```

### POST `/tasks/{taskId}/archive`

软归档任务。

## 5. 目标和行动

### PATCH `/goals/{goalId}`

需要 `version`。

## 6. 时间块和时间线

### GET `/schedule-blocks`

查询参数：`from`、`to`、`timezone`。

### POST `/schedule-blocks`

```json
{
  "taskId": "uuid",
  "startsAt": "2026-09-16T19:00:00+08:00",
  "endsAt": "2026-09-16T19:30:00+08:00",
  "timezone": "Asia/Shanghai",
  "source": "manual"
}
```

响应包含冲突：

```json
{
  "data": {
    "id": "uuid",
    "startsAtUtc": "2026-09-16T11:00:00Z",
    "endsAtUtc": "2026-09-16T11:30:00Z",
    "conflictState": "warning",
    "conflicts": ["other-block-id"]
  }
}
```

### PATCH `/schedule-blocks/{blockId}`

移动或修改时长，需要 `version`。

### DELETE `/schedule-blocks/{blockId}`

取消时间块，不删除关联任务。

## 8. 开销

### GET `/expenses`

支持日期范围、分类、生活领域、目标和分页。

### POST `/expenses`

```json
{
  "amountMinor": "3600",
  "currencyCode": "CNY",
  "categoryId": "uuid",
  "lifeAreaId": "uuid",
  "goalId": null,
  "occurredOn": "2026-09-16",
  "paymentMethod": "wechat",
  "note": "晚饭"
}
```

金额使用最小货币单位字符串传输，避免 JavaScript 大整数精度问题。

### PATCH `/expenses/{expenseId}`

需要 `version`，修改金额需要保留更新时间。

### DELETE `/expenses/{expenseId}`

软删除并返回可撤销信息。

### GET `/expense-summary`

查询参数：`from`、`to`、`groupBy=category|lifeArea|goal`。

## 9. 日周复盘

### GET `/reviews/daily/{date}`

返回指定日期的事实摘要和用户填写内容。

当日尚无复盘（用户未填写、且无事实摘要）时，**不是 404**，而是 200 且 `data` 为 `null`——「成功但没有内容」，与「请求失败」必须分开（404/5xx 走错误态，`data: null` 走空态）：

```json
{
  "data": null,
  "meta": {
    "requestId": "req_123",
    "serverTime": "2026-09-20T10:00:00Z"
  }
}
```

### PUT `/reviews/daily/{date}`

```json
{
  "answers": {
    "completed": "完成了整理资料",
    "blocker": "临时加班",
    "nextAdjustment": "明天只安排 20 分钟"
  },
  "energyLevel": "low"
}
```

### GET `/reviews/weekly/{weekStart}`

返回计划/实际、延期、目标行动和开销摘要。

### POST `/reviews/weekly/{weekStart}/adjustments`

```json
{
  "targetType": "task",
  "targetId": "uuid",
  "action": "shorten",
  "payload": {
    "estimatedMinutes": 20
  }
}
```

## 11. 同步

### POST `/sync/push`

提交本地 outbox 操作：

```json
{
  "operations": [
    {
      "operationId": "uuid",
      "entityType": "task",
      "entityId": "uuid",
      "operationType": "update",
      "baseVersion": 4,
      "payload": {
        "title": "更新后的任务"
      }
    }
  ]
}
```

响应返回每个操作的状态：applied、already_applied、conflict、rejected。

### GET `/sync/pull`

参数：`cursor`、`limit`。

返回当前用户自游标之后的变更和新游标。

### POST `/sync/conflicts/{conflictId}/resolve`

```json
{
  "resolution": "keep_server|keep_local|manual_merge",
  "mergedPayload": {}
}
```

## 12. 数据导出和删除

### POST `/data-exports`

创建导出任务，返回任务 ID；导出可能异步完成。

### GET `/data-exports/{exportId}`

返回状态和短期下载地址。

### POST `/data-imports/preview`

上传用户导出的 JSON，先返回预览和冲突数量，不直接写入。

### POST `/data-imports/{importId}/confirm`

确认导入，支持 merge 或 replace；replace 必须二次确认。

### POST `/account/deletion-request`

发起账户删除，进入可撤销窗口后再异步清理。

## 13. API 安全与限流

- 每个请求必须做用户身份和资源归属校验。
- 列表接口强制分页和上限。
- AI 接口按用户和 IP 限流。
- 导入、导出和删除接口需要更严格限流。
- 所有外部输入使用 schema 校验。
- 错误不返回内部堆栈、SQL、密钥或完整用户数据。
- 写请求支持幂等键。

## 14. 系统

### GET `/health`

只读，**无鉴权**。返回服务存活状态，供部署探针与自动化测试使用。

响应体固定为 `{ "status": "ok" }`。

当前**不**检查数据库连通性与外部依赖；真正的存活/就绪探针属于 OPS 阶段。

### ALL `/[[...slug]]`

`/api/v1` 下未匹配任何已登记路径时的兜底，返回 404 与 §1.4 的标准错误结构（`NOT_FOUND`）。

用**可选** catch-all：`[...slug]` 不匹配 `/api/v1` 本身，而裸访问该前缀同样应当得到结构化 404。

它不提供任何数据，存在的意义是让「API 下一切失败都是统一结构」没有例外——
否则客户端按 JSON 解析时会在最不该出问题的 404 上拿到 HTML。
