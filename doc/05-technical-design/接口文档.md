# Livefil API 接口文档

> 版本：v0.1  
> 协议：HTTPS + REST/JSON  
> API 前缀：`/api/v1`  
> 日期：2026-09-15

## 1. 通用约定

### 1.1 请求头

```http
Content-Type: application/json
Accept: application/json
Authorization: Bearer <access-token>
X-Request-Id: <client-request-id>
Idempotency-Key: <unique-key-for-write-request>
```

`Authorization` 在本地模式可省略；云端模式必须由服务端识别用户。

写操作建议携带 `Idempotency-Key`。客户端重试同一业务操作时必须复用相同 key。

### 1.2 成功响应

```json
{
  "data": {},
  "meta": {
    "requestId": "req_123",
    "serverTime": "2026-09-15T10:00:00Z"
  }
}
```

### 1.3 分页响应

```json
{
  "data": [],
  "meta": {
    "requestId": "req_123",
    "nextCursor": "cursor_value",
    "hasMore": true
  }
}
```

### 1.4 错误响应

```json
{
  "error": {
    "code": "VALIDATION_ERROR",
    "message": "任务标题不能为空",
    "fields": {
      "title": "required"
    },
    "requestId": "req_123"
  }
}
```

错误码：

| HTTP | code | 说明 |
|---:|---|---|
| 400 | `VALIDATION_ERROR` | 输入不合法 |
| 401 | `AUTHENTICATION_REQUIRED` | 未登录或令牌失效 |
| 403 | `FORBIDDEN` | 无权访问 |
| 404 | `NOT_FOUND` | 资源不存在或不属于当前用户 |
| 409 | `CONFLICT` | 版本冲突或重复操作 |
| 409 | `IDEMPOTENCY_REPLAY` | 操作已经处理 |
| 429 | `RATE_LIMITED` | 超过限流或 AI 配额 |
| 502 | `DEPENDENCY_UNAVAILABLE` | 外部服务不可用 |
| 504 | `DEPENDENCY_TIMEOUT` | 外部服务超时 |
| 500 | `INTERNAL_ERROR` | 未预期错误 |

## 2. 认证与用户

> 实现状态（2026-09-20）：Phase 2 只交付**本地单用户模式**；邀请制云端账号挂账（决策 T-006）。

### POST `/auth/local/session`

创建（幂等确保）本地模式会话。**无需请求体、无需凭证**：服务端在单事务内确保唯一本地用户与默认生活领域存在，经 `Set-Cookie` 下发签名会话。

响应：

```json
{
  "data": {
    "mode": "local",
    "userId": "uuid"
  }
}
```

`Set-Cookie`：HttpOnly、SameSite=Lax（生产环境 Secure）、Path=/。重复调用幂等，不产生第二个用户。

### POST `/auth/cloud/request-link` 〔挂账·本批未实现〕

邀请账号模式的登录链接/验证码端点。本批不实现（请求落入 FND-005 结构化 404）；认证方式（邮箱密码或魔法链接二选一）待云端批次拍板，不接社交登录。

### GET `/me`

获取当前用户设置与数据模式。本地模式下无有效会话 Cookie 时，经 EnsureLocalSession 自动初始化——响应 200 并 `Set-Cookie`，**不返回 401**。

响应 `data`：

```json
{
  "id": "uuid",
  "mode": "local",
  "displayName": null,
  "locale": "zh-CN",
  "timezone": "Asia/Shanghai",
  "currencyCode": "CNY",
  "weekStartsOn": 1,
  "defaultTaskDurationMinutes": 30,
  "defaultBufferMinutes": 10,
  "aiEnabled": false,
  "aiDataConsent": false,
  "reminderEnabled": true,
  "quietHoursStart": "22:00",
  "quietHoursEnd": "08:00",
  "version": "3"
}
```

### PATCH `/me`

更新设置；字段同 GET（除 id、mode），均可选。经 Zod 校验，**单事务整体成功或失败，无部分更新**。

跨字段约束：`aiEnabled=true` 要求 `aiDataConsent=true`。

成功返回更新后的完整设置（同 GET data）与自增 `version`。

错误：

- 422 `VALIDATION_ERROR`：locale/timezone 不受支持、currencyCode 非 3 字母、weekStartsOn 越界（0–6）、时长/缓冲为负、安静时段非法、AI 同意约束不满足。
- 409 `CONFLICT`：`version` 与当前不符。

## 3. 生活领域

### GET `/life-areas`

返回当前用户的生活领域，按 `sortOrder` 升序。

查询参数：

- `includeArchived`：默认 `false` 仅未归档；`true` 时含已归档（供「显示已归档」查看）。

### POST `/life-areas`

```json
{
  "name": "健康",
  "colorKey": "green"
}
```

校验：名称必填、≤60 字符；colorKey 必须是分类色集合之一——`blue` | `green` | `amber` | `violet` | `teal` | `rose`（定义见 UI 规范 §2.1，该枚举为契约），缺省取 `blue`；不存前端色值。新领域 sortOrder 取末位。

错误：422 `VALIDATION_ERROR`；409 `CONFLICT`（同用户未归档同名）。

### PATCH `/life-areas/{lifeAreaId}`

更新名称、colorKey（枚举同 POST）或归档状态（字段均可选）：

```json
{ "name": "身心健康", "isArchived": false }
```

归档（`isArchived:true`）只置标志位、不删行，历史关联保持可解析；重复归档返回 422。

### POST `/life-areas/reorder`

批量排序（单事务，避免多次 PATCH 产生中间错乱状态）：

```json
{ "orderedIds": ["uuid-1", "uuid-2", "uuid-3"] }
```

`orderedIds` 必须恰好等于当前用户全部未归档领域集合（多、少、含他人/已归档 id → 422）；成功后按列表顺序重排 sortOrder。

### DELETE `/life-areas/{lifeAreaId}`

**语义＝归档**（置 is_archived），不删除历史任务、目标和开销关联；非本人或不存在的 id 返回 404（不泄露存在性）。

## 4. 任务和收件箱

### GET `/tasks`

查询参数：

- `status`
- `from`
- `to`
- `lifeAreaId`
- `goalId`
- `cursor`
- `limit`

口径：固定按 `createdAt desc` 返回（不开放排序键；对应 UI 规范「按最近添加」）；
`limit` 默认 **20**、范围 1–100；`cursor` 不透明，终态 `meta.hasMore=false`。
已软删（deleted_at）的任务不出现在任何查询中。

### POST `/tasks`

请求体（仅 `title` 必填；对应 SRS FR-010）：

| 字段 | 类型 | 说明 |
|---|---|---|
| `title` | string | 必填，空 / 超长返回 `VALIDATION_ERROR` |
| `status` | enum | `inbox`（默认）/`planned` 等，合法流转见 SRS §9.1 |
| `lifeAreaId` | uuid | 可空，须属于当前用户 |
| `dueDate` | date | 可空，`YYYY-MM-DD`；给出时通常即「保存到指定日期」 |
| `estimatedMinutes` | integer | 可空，正整数 |
| `minimumVersion` | string | 可空 |
| `goalId` | uuid | 可空，须属于当前用户 |
| `actionId` | uuid | 可空，须属于该 `goalId` 下的行动 |

```json
{
  "title": "整理项目资料",
  "lifeAreaId": "uuid",
  "goalId": "uuid",
  "dueDate": "2026-09-22",
  "estimatedMinutes": 45,
  "minimumVersion": "只整理 10 分钟",
  "status": "inbox"
}
```

重复提交口径（2026-09-21 统一）：客户端负责按钮防连点；写请求建议携带
`Idempotency-Key`（见 §1.1）——携带时服务端经 `idempotency_keys`（《数据库设计》
§4.15）识别，重复请求重放首次结果、返回 `IDEMPOTENCY_REPLAY`，不产生第二条任务；
**未携带** key 时按 POST 自然语义各自独立落库。关联实体不属于当前用户时返回
`RELATED_ENTITY_NOT_FOUND`。

### GET `/tasks/{taskId}`

返回任务、关联目标、时间块摘要和最近执行记录。

> Phase 3 边界：时间块与执行记录分别属 Phase 4（`schedule_blocks` /
> `execution_logs`），本批它们一律返回空集合（`[]`）而非省略字段，
> 也不得造样例数据；目标关联正常返回。

### PATCH `/tasks/{taskId}`

必须携带 `version`，服务端执行乐观并发校验。

```json
{
  "title": "整理项目资料和链接",
  "version": 3
}
```

### POST `/tasks/{taskId}/status`

请求体：

| 字段 | 类型 | 说明 |
|---|---|---|
| `status` | enum | 目标状态，须符合完整流转表（《数据库设计》§4.5，含重开/恢复），非法跳转返回 `VALIDATION_ERROR` |
| `reasonCode` | enum | 可空，合法集合见下 |
| `note` | string | 可空一句话，不进日志原文 |
| `actualMinutes` | integer | 可空正整数，部分完成 / 完成时记实际时长（SRS FR-012） |
| `actualAmount` | string | 可空，部分完成时记实际完成量（自由文本/数值字符串；**非金额**，不适用整数分规则） |

```json
{
  "status": "deferred",
  "reasonCode": "NO_ENERGY",
  "note": "今天临时加班"
}
```

`reasonCode` 合法集合（开放扩展须规范升版；不传即可，不强制枚举）：

- `NO_ENERGY`（没精力）
- `NO_TIME`（没时间）
- `CONFLICT`（临时冲突/被打断）
- `TOO_HARD`（比预想难）
- `NOT_IN_MOOD`（不在状态）

每次状态流转写一条状态事件（`audit` 通道，含类型/结果/时间/匿名标识）。
`actualMinutes` / `actualAmount` 在本批随状态事件保存；进入 `execution_logs`
的持久化汇总自 Phase 4 接入，本批不提前写该表。

### POST `/tasks/{taskId}/convert-to-action`

把收件箱/未安排任务快速转为某目标下的行动（SRS FR-011 精神，PRD §4.2）。

请求体：

| 字段 | 类型 | 说明 |
|---|---|---|
| `goalId` | uuid | 必填，须属于当前用户 |
| `name` | string | 可空，默认取任务标题 |
| `minimumVersion` | string | 可空，默认取任务的 `minimumVersion` |
| `estimatedMinutes` | integer | 可空，默认取任务的 `estimatedMinutes` |

行为（单事务）：

1. 在该目标下创建一条 `action`；
2. 回填任务的 `goalId` 与 `actionId`，任务状态由 `inbox` 置为 `planned`；
3. **任务保留不删除**；之后可经 PATCH 清空关联而不影响任务（取消关联不删任务）。

### POST `/tasks/batch`

批量整理收件箱（PRD §4.2：批量归档与批量安排；不提供批量删除）。

请求体：

| 字段 | 类型 | 说明 |
|---|---|---|
| `taskIds` | uuid[] | 必填，1 至多 100 个，须均属于当前用户 |
| `operation` | enum | `archive` / `schedule` |
| `dueDate` | date | `schedule` 时使用，可空 |
| `lifeAreaId` | uuid | `schedule` 时可空，须属于当前用户 |

```json
{ "taskIds": ["uuid-a", "uuid-b"], "operation": "schedule", "dueDate": "2026-09-23" }
```

- 整体在**单事务**内执行：任一 id 不存在 / 不属于当前用户 / 状态不允许该操作，
  整批失败（`RELATED_ENTITY_NOT_FOUND` 或 `VALIDATION_ERROR`），不产生部分写入。
- `archive`：批量置 `archived`；`schedule`：批量置 `dueDate`（给出时）/`lifeAreaId`，
  状态按 SRS §9.1 进入 `planned`。
- 每个被改动任务各写一条状态事件。

### POST `/tasks/{taskId}/archive`

软归档任务。

### DELETE `/tasks/{taskId}`

删除任务（SRS FR-011）：软删，置 `deleted_at`；与归档不同——删除后任务不进入
任何列表，归档仍可在「显示已归档」中查看。无需 `version`。
对不存在 / 已删除的任务重复删除返回 404。
收件箱支持删除，但不提供批量删除。

## 5. 目标和行动

### GET `/goals`

支持 `status`、`lifeAreaId`、`cursor` 和 `limit`。

### POST `/goals`

```json
{
  "name": "改善体能",
  "lifeAreaId": "uuid",
  "reason": "希望有更稳定的精力",
  "targetDate": "2026-12-31"
}
```

### GET `/goals/{goalId}`

返回目标、行动、行动进度和关联开销摘要。

> Phase 3 边界：关联开销属 Phase 6，本批返回空集合（`[]`）；
> 行动与行动进度（由行动状态汇总）正常返回，结果进度取 `resultMetric`。

### PATCH `/goals/{goalId}`

需要 `version`。可更新名称、理由、日期、状态与 `resultMetric`（结果进度手动更新，
结构见《数据库设计》§4.3：`current`/`target`/`unit`/`note`）。

```json
{
  "version": 2,
  "resultMetric": { "current": 3, "target": 5, "unit": "次" }
}
```

服务端不据 `current/target` 自动判定目标完成；目标状态仍由显式状态更新驱动。

### POST `/goals/{goalId}/actions`

```json
{
  "name": "本周运动 3 次",
  "targetFrequency": {
    "period": "week",
    "count": 3
  },
  "estimatedMinutes": 30,
  "minimumVersion": "散步 8 分钟"
}
```

### PATCH `/actions/{actionId}`

更新行动状态、频率、最低版本和预计时长；必须携带 `version`（乐观并发，
口径同 PATCH `/goals/{goalId}`）。

### DELETE `/actions/{actionId}`

删除行动：软删（`deleted_at`）。有关联任务时在同一事务把任务的 `actionId` 置空
（`goalId` 保留、任务不删；语义见《数据库设计》§4.4）。对不存在 / 已删除的
行动重复删除返回 404。

## 6. 排程：时间块、固定事项与今日时间线

> 2026-09-21 Phase 4 冻结：时间块端点补齐字段表与冲突回传；新增
> `/fixed-commitments` 与 `GET /today`（决策：今日页一次聚合，不前端拼请求）。

### GET `/schedule-blocks`

查询参数：

| 参数 | 必填 | 说明 |
|---|---|---|
| `from`、`to` | 是 | 日历日 `YYYY-MM-DD`（含端点），按 `timezone` 解释 |
| `timezone` | 是 | IANA 时区名 |
| `includeCancelled` | 否 | 默认 `false` |

- 窗口跨度 ≤ 42 天，超出 `VALIDATION_ERROR`；窗口内不分页，返回数组。
- 排序：`startsAtUtc` 升序；窗口内触发重复任务物化（《数据库设计》§4.5）。
- 周视图使用本端点（周窗口），不另设端点。

### POST `/schedule-blocks`

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `taskId` | uuid | 否 | **可空：自由块**；给出时必须属当前用户 |
| `actionId` | uuid | 否 | 须属当前用户 |
| `startsAt` | ISO 8601 带偏移 | 是 | |
| `endsAt` | ISO 8601 带偏移 | 是 | 须晚于 startsAt |
| `timezone` | IANA | 是 | |
| `source` | enum | 否 | 默认 `manual`；`routine` 仅服务端内部使用 |

```json
{
  "taskId": "uuid",
  "startsAt": "2026-09-16T19:00:00+08:00",
  "endsAt": "2026-09-16T19:30:00+08:00",
  "timezone": "Asia/Shanghai",
  "source": "manual"
}
```

响应包含冲突：

```json
{
  "data": {
    "id": "uuid",
    "taskId": "uuid",
    "startsAtUtc": "2026-09-16T11:00:00Z",
    "endsAtUtc": "2026-09-16T11:30:00Z",
    "status": "planned",
    "version": 1,
    "conflictState": "warning",
    "conflicts": [
      { "id": "other-block-id", "kind": "block",
        "startsAtUtc": "2026-09-16T11:15:00Z", "endsAtUtc": "2026-09-16T11:45:00Z" },
      { "id": "fixed-id", "kind": "fixed",
        "startsAtUtc": "2026-09-16T12:00:00Z", "endsAtUtc": "2026-09-16T13:00:00Z" }
    ]
  }
}
```

- 冲突检测：与未取消的 `schedule_blocks` 和当日 `fixed_commitments` 实例做
  半开区间 `[starts, ends)` 比较——**重叠才冲突、相邻不撞**；跨时区一律换算 UTC。
- 有重叠：`conflictState='warning'`；用户显式「仍要保留」后服务端记
  `'confirmed'`（经 PATCH）。`conflicts` 元素含 `kind: block | fixed`
  （2026-09-21 冻结，取代旧示例的纯 ID 数组）。

### PATCH `/schedule-blocks/{blockId}`

移动或修改时长；必须携带 `version`（409＝`CONFLICT`）。

- 字段同 POST（均可选）；改动时间后 `planned` 块状态转 `adjusted`。
- `completed`/`cancelled` 块不可移动（`VALIDATION_ERROR`，需先恢复/重建）。
- **保存后重新检测冲突**，响应体与 POST 同形（含 `conflictState`、`conflicts`）。

### DELETE `/schedule-blocks/{blockId}`

取消时间块（终态 `cancelled`），不删除关联任务、不改任务状态；重复删除返 404。

### GET `/fixed-commitments`

参数与窗口限制同 GET `/schedule-blocks`；返回数组，按 `startsAtUtc` 升序；
窗口内触发重复固定事项物化。

### POST `/fixed-commitments`

单次事项：

```json
{ "title": "门诊复诊",
  "startsAt": "2026-09-28T14:00:00+08:00",
  "endsAt": "2026-09-28T15:00:00+08:00",
  "timezone": "Asia/Shanghai" }
```

重复模板（钟点本地解释，DST 安全）：

```json
{ "title": "线下坐班",
  "startsAtLocal": "09:00",
  "durationMinutes": 540,
  "recurrenceRule": { "freq": "weekly", "weekdays": [1, 2, 3, 4, 5] },
  "timezone": "Asia/Shanghai" }
```

- 字段：`title` 必填 ≤240；单次形态必填 startsAt/endsAt；重复形态必填
  startsAtLocal/durationMinutes/recurrenceRule；两形态混用 `VALIDATION_ERROR`。
- 写入不回传 conflicts（不做窗口扫描）；冲突在块创建与 `/today` 中检出。
- 201 返回创建对象（模板或单次事项）。

### PATCH `/fixed-commitments/{commitmentId}`

必须携带 `version`。PATCH 实例行＝只改当前一次；PATCH 模板行＝改未来规则，
历史实例不重写（UI 必须先问「当前一次 / 未来所有」，语义同 §4.5 任务物化）。

### DELETE `/fixed-commitments/{commitmentId}`

软删；对实例行只删一次、对模板行不影响已生成实例；重复删除返 404。

### GET `/today`

今日一屏聚合（FR-030）；查询参数：`date`（可选，默认当日）、`timezone`（必填）。

```json
{
  "data": {
    "date": "2026-09-22",
    "currentAction": { "blockId": "uuid", "title": "阅读", "startsAtUtc": "…", "endsAtUtc": "…" },
    "blocks": [],
    "fixedCommitments": [],
    "unscheduledTasks": [ { "id": "uuid", "title": "…", "dueDate": "2026-09-20", "overdue": true } ],
    "routines": [
      { "id": "uuid", "name": "晨间例程", "scheduled": true,
        "steps": [ { "id": "uuid", "title": "喝水", "blockId": "uuid", "status": "completed" } ] }
    ],
    "habits": [ { "actionId": "uuid", "goalId": "uuid", "title": "拉伸", "targetFrequency": 3, "doneToday": false } ],
    "load": { "fixedMinutes": 540, "plannedMinutes": 240, "completedMinutes": 30,
              "availableMinutes": 420, "overloaded": true },
    "recovery": { "manual": false, "since": null, "autoTriggered": true,
                  "suggestions": [ { "code": "SHRINK", "target": "block-id", "text": "先做最低版本（约 8 分钟）" } ] }
  }
}
```

口径：

- `blocks`：当日未取消块，按开始升序；`currentAction`＝当前时刻所在块（克制，无则 null）。
- `unscheduledTasks`：`planned`、`due_date ≤ date` 且当日无未取消块的任务实例；
  上限 50。
- `routines`：规则命中当日的 active 例程（含各步块状态）；`habits`＝active
  目标下带 `targetFrequency` 的行动（无独立 habits 表），`doneToday` 据当日
  execution_logs 判定。
- `load`：fixedMinutes＝固定事项时长合计；plannedMinutes＝块时长合计；
  availableMinutes＝960（16h 清醒窗口，暂不开放配置）− fixedMinutes；
  completedMinutes＝当日已完成块时长；overloaded＝planned > available。
- `recovery` 口径见 §7 恢复模式。

## 7. 执行记录与恢复模式

### POST `/execution-logs`

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `taskId` | uuid | 否 | 须属当前用户 |
| `scheduleBlockId` | uuid | 否 | 须属当前用户；与 taskId 至少给一个（自由块只给块 ID） |
| `status` | enum | 是 | `completed` / `minimum_completed` / `partial` / `deferred` / `skipped` |
| `plannedMinutes` | integer | 否 | ≥0 |
| `actualMinutes` | integer | 否 | ≥0 |
| `reasonCode` | enum | 否 | `NO_ENERGY`/`NO_TIME`/`CONFLICT`/`TOO_HARD`/`NOT_IN_MOOD`；仅 partial/deferred/skipped 可带 |
| `energyLevel` | enum | 否 | `low`/`medium`/`high` |
| `moodScore` | integer | 否 | 1–5 |
| `note` | string | 否 | ≤500；不进普通日志 |
| `occurredAt` | ISO 8601 | 否 | 缺省服务端当前时刻；支持回填补记 |

```json
{
  "taskId": "uuid",
  "scheduleBlockId": "uuid",
  "status": "minimum_completed",
  "plannedMinutes": 30,
  "actualMinutes": 8,
  "occurredAt": "2026-09-16T11:10:00Z"
}
```

- **必须携带 `Idempotency-Key` 请求头**（见 §1.1；2026-09-21 归位入此字段区）；
  同 key 重放返回 409 `IDEMPOTENCY_REPLAY`。
- 联动（与块状态口径，见《数据库设计》§4.6/4.8）：
  - `completed` / `minimum_completed`：关联块转 `completed`；关联任务转
    `completed`（最低版本在 tasks 不单列）。
  - `partial`：块转 `completed`，任务进 `partial`。
  - `deferred` / `skipped`：任务分别进 `deferred` / `skipped`；块置
    `cancelled`（该次安排作废）。
- 记录追加式，无修改端点。

### GET `/execution-logs`

- 查询参数：`from`、`to`（日历日，窗口 ≤ 92 天）、`taskId`、`actionId`、
  `status`、`timezone`；游标分页（结构见 §1.3），`limit` ≤ 100（默认 50）。
- 排序：`occurredAt` 降序；软删任务的历史记录仍保留，
  账户删除随 data-management 批次处理。

### PUT `/recovery-mode`

手动进入/退出恢复模式（FR-042）：

```json
{ "enabled": true }
```

- 持久化于 `recovery_states`（仅记手动态与 `since`）；进入后当日与后续
  `/today` 的建议按 domain 规则生成，退出＝`{ "enabled": false }`。
- 用户可随时手动进入；自动提示无需开关，见下。

**自动提示与建议生成口径（2026-09-21 冻结，规则落 domain 层、非前端文案）：**

- 统计：回看最近 7 个有计划任务的日子（当天至少有一个 planned 块），
  若其中连续 2 天完成率 < 50%（完成率＝当日 completed+minimum_completed 的
  execution_logs 对应计划分钟 / 当日 plannedMinutes），`/today` 的
  `recovery.autoTriggered=true`，仅给一条轻量中性提示，可忽略、不自动改计划。
- 手动恢复模式下，建议按以下顺序对**今日未完成块**生成（文案中性，
  不做归零/惩罚/ streak 清零）：
  1. `overloaded=true` → 对可压缩块建议 `SHRINK`（减量）；
  2. 任务/行动有 `minimumVersion` → 建议 `MINIMUM`（切最低版本）；
  3. 块时刻已过 → 建议 `RESCHEDULE`（重排到今日空档，仅建议不落库）；
  4. 无可行空档 → 建议 `PAUSE`（暂停当日计划，明日重来）。

## 8. 例程

> 2026-09-21 Phase 4 新增。实例化口径＝物化到 schedule_blocks（决策项，
> 见《数据库设计》§4.6/4.7）。

### GET `/routines`

返回当前用户全部未删除例程（数组，`name` 升序），含 `steps`（按 position）。

### POST `/routines`

```json
{ "name": "晨间例程", "lifeAreaId": "uuid",
  "recurrenceRule": { "freq": "weekly", "weekdays": [1, 2, 3, 4, 5] },
  "anchorTime": "07:00", "timezone": "Asia/Shanghai",
  "steps": [ { "title": "喝水", "estimatedMinutes": 5 },
             { "title": "拉伸", "estimatedMinutes": 10, "minimumVersion": "2 分钟" } ] }
```

- `name`、`recurrenceRule`、`timezone` 必填；`steps` ≥ 1、≤ 20，
  position 由数组顺序给定（从 0）。201 返回带 id/version 的例程。

### PATCH `/routines/{routineId}`

必须携带 `version`；可改定义字段与步骤集合（步骤携带 id 者更新、不带 id 者新增、
  缺失者软删）；position 重排后仍须连续。**不重写已生成的块。**

### DELETE `/routines/{routineId}`

软删例程；已生成块保留；重复删除返 404。

### POST `/routines/{routineId}/schedule`

把例程安排到某日并物化：

```json
{ "date": "2026-09-23", "startAt": "07:00", "timezone": "Asia/Shanghai" }
```

- 按步骤顺序展开为 `schedule_blocks`（`source='routine'`，回填溯源列）；
  同日重复调用幂等：已存在该例程当日块时返回 409 `CONFLICT`（不重复生成）。
- 响应：`{ "data": [ …生成的块… ] }`，各块带正常冲突检测结果。

## 14. API 安全与限流

- 每个请求必须做用户身份和资源归属校验。
- 列表接口强制分页和上限。
- AI 接口按用户和 IP 限流。
- 导入、导出和删除接口需要更严格限流。
- 所有外部输入使用 schema 校验。
- 错误不返回内部堆栈、SQL、密钥或完整用户数据。
- 写请求支持幂等键。

## 15. 系统

### GET `/health`

只读，**无鉴权**。返回服务存活状态，供部署探针与自动化测试使用。

响应体固定为 `{ "status": "ok" }`。

当前**不**检查数据库连通性与外部依赖；真正的存活/就绪探针属于 OPS 阶段。

### ALL `/[[...slug]]`

`/api/v1` 下未匹配任何已登记路径时的兜底，返回 404 与 §1.4 的标准错误结构（`NOT_FOUND`）。

用**可选** catch-all：`[...slug]` 不匹配 `/api/v1` 本身，而裸访问该前缀同样应当得到结构化 404。

它不提供任何数据，存在的意义是让「API 下一切失败都是统一结构」没有例外——
否则客户端按 JSON 解析时会在最不该出问题的 404 上拿到 HTML。
