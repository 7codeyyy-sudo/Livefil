# Livefil API 接口文档

> 版本：v0.1  
> 协议：HTTPS + REST/JSON  
> API 前缀：`/api/v1`  
> 日期：2026-09-15

## 1. 通用约定

### 1.1 请求头

```http
Content-Type: application/json
Accept: application/json
Authorization: Bearer <access-token>
X-Request-Id: <client-request-id>
Idempotency-Key: <unique-key-for-write-request>
```

`Authorization` 在本地模式可省略；云端模式必须由服务端识别用户。

写操作建议携带 `Idempotency-Key`。客户端重试同一业务操作时必须复用相同 key。

### 1.2 成功响应

```json
{
  "data": {},
  "meta": {
    "requestId": "req_123",
    "serverTime": "2026-09-15T10:00:00Z"
  }
}
```

### 1.3 分页响应

```json
{
  "data": [],
  "meta": {
    "requestId": "req_123",
    "nextCursor": "cursor_value",
    "hasMore": true
  }
}
```

### 1.4 错误响应

```json
{
  "error": {
    "code": "VALIDATION_ERROR",
    "message": "任务标题不能为空",
    "fields": {
      "title": "required"
    },
    "requestId": "req_123"
  }
}
```

错误码：

| HTTP | code | 说明 |
|---:|---|---|
| 400 | `VALIDATION_ERROR` | 输入不合法 |
| 401 | `AUTHENTICATION_REQUIRED` | 未登录或令牌失效 |
| 403 | `FORBIDDEN` | 无权访问 |
| 404 | `NOT_FOUND` | 资源不存在或不属于当前用户 |
| 409 | `CONFLICT` | 版本冲突或重复操作 |
| 409 | `IDEMPOTENCY_REPLAY` | 操作已经处理 |
| 429 | `RATE_LIMITED` | 超过限流或 AI 配额 |
| 502 | `DEPENDENCY_UNAVAILABLE` | 外部服务不可用 |
| 504 | `DEPENDENCY_TIMEOUT` | 外部服务超时 |
| 500 | `INTERNAL_ERROR` | 未预期错误 |

## 2. 认证与用户

### POST `/auth/local/session`

创建本地模式会话。

响应：

```json
{
  "data": {
    "mode": "local",
    "userId": "uuid",
    "sessionToken": "local-session-token"
  }
}
```

### POST `/auth/cloud/request-link`

邀请账号模式请求登录链接或登录验证码。实际采用密码或魔法链接由认证实现确认。

### GET `/me`

获取当前用户设置和数据模式。

### PATCH `/me`

更新语言、时区、货币、周起始日、提醒和 AI 设置。

示例：

```json
{
  "locale": "zh-CN",
  "timezone": "Asia/Shanghai",
  "currencyCode": "CNY",
  "weekStartsOn": 1
}
```

## 3. 生活领域

### GET `/life-areas`

返回当前用户未归档生活领域。

### POST `/life-areas`

```json
{
  "name": "健康",
  "colorKey": "green"
}
```

### PATCH `/life-areas/{lifeAreaId}`

更新名称、排序或归档状态。

### DELETE `/life-areas/{lifeAreaId}`

软删除/归档领域，不删除历史任务和开销。

## 4. 任务和收件箱

### GET `/tasks`

查询参数：

- `status`
- `from`
- `to`
- `lifeAreaId`
- `goalId`
- `cursor`
- `limit`

### POST `/tasks`

```json
{
  "title": "整理项目资料",
  "lifeAreaId": "uuid",
  "estimatedMinutes": 45,
  "minimumVersion": "只整理 10 分钟",
  "status": "inbox"
}
```

### GET `/tasks/{taskId}`

返回任务、关联目标、时间块摘要和最近执行记录。

### PATCH `/tasks/{taskId}`

必须携带 `version`，服务端执行乐观并发校验。

```json
{
  "title": "整理项目资料和链接",
  "version": 3
}
```

### POST `/tasks/{taskId}/status`

```json
{
  "status": "deferred",
  "reasonCode": "NO_ENERGY",
  "note": "今天临时加班"
}
```

### POST `/tasks/{taskId}/archive`

软归档任务。

## 5. 目标和行动

### GET `/goals`

支持 `status`、`lifeAreaId`、`cursor` 和 `limit`。

### POST `/goals`

```json
{
  "name": "改善体能",
  "lifeAreaId": "uuid",
  "reason": "希望有更稳定的精力",
  "targetDate": "2026-12-31"
}
```

### GET `/goals/{goalId}`

返回目标、行动、行动进度和关联开销摘要。

### PATCH `/goals/{goalId}`

需要 `version`。

### POST `/goals/{goalId}/actions`

```json
{
  "name": "本周运动 3 次",
  "targetFrequency": {
    "period": "week",
    "count": 3
  },
  "estimatedMinutes": 30,
  "minimumVersion": "散步 8 分钟"
}
```

### PATCH `/actions/{actionId}`

更新行动状态、频率、最低版本和预计时长。

## 6. 时间块和时间线

### GET `/schedule-blocks`

查询参数：`from`、`to`、`timezone`。

### POST `/schedule-blocks`

```json
{
  "taskId": "uuid",
  "startsAt": "2026-09-16T19:00:00+08:00",
  "endsAt": "2026-09-16T19:30:00+08:00",
  "timezone": "Asia/Shanghai",
  "source": "manual"
}
```

响应包含冲突：

```json
{
  "data": {
    "id": "uuid",
    "startsAtUtc": "2026-09-16T11:00:00Z",
    "endsAtUtc": "2026-09-16T11:30:00Z",
    "conflictState": "warning",
    "conflicts": ["other-block-id"]
  }
}
```

### PATCH `/schedule-blocks/{blockId}`

移动或修改时长，需要 `version`。

### DELETE `/schedule-blocks/{blockId}`

取消时间块，不删除关联任务。

## 7. 执行记录

### POST `/execution-logs`

```json
{
  "taskId": "uuid",
  "scheduleBlockId": "uuid",
  "status": "minimum_completed",
  "plannedMinutes": 30,
  "actualMinutes": 8,
  "occurredAt": "2026-09-16T11:10:00Z"
}
```

执行记录接口必须支持 `Idempotency-Key`。

### GET `/execution-logs`

支持日期范围、任务、目标和状态筛选。

## 8. 开销

### GET `/expenses`

支持日期范围、分类、生活领域、目标和分页。

### POST `/expenses`

```json
{
  "amountMinor": "3600",
  "currencyCode": "CNY",
  "categoryId": "uuid",
  "lifeAreaId": "uuid",
  "goalId": null,
  "occurredOn": "2026-09-16",
  "paymentMethod": "wechat",
  "note": "晚饭"
}
```

金额使用最小货币单位字符串传输，避免 JavaScript 大整数精度问题。

### PATCH `/expenses/{expenseId}`

需要 `version`，修改金额需要保留更新时间。

### DELETE `/expenses/{expenseId}`

软删除并返回可撤销信息。

### GET `/expense-summary`

查询参数：`from`、`to`、`groupBy=category|lifeArea|goal`。

## 9. 日周复盘

### GET `/reviews/daily/{date}`

返回指定日期的事实摘要和用户填写内容。

### PUT `/reviews/daily/{date}`

```json
{
  "answers": {
    "completed": "完成了整理资料",
    "blocker": "临时加班",
    "nextAdjustment": "明天只安排 20 分钟"
  },
  "energyLevel": "low"
}
```

### GET `/reviews/weekly/{weekStart}`

返回计划/实际、延期、目标行动和开销摘要。

### POST `/reviews/weekly/{weekStart}/adjustments`

```json
{
  "targetType": "task",
  "targetId": "uuid",
  "action": "shorten",
  "payload": {
    "estimatedMinutes": 20
  }
}
```

## 10. AI

### POST `/ai/drafts/task-breakdown`

```json
{
  "text": "我想准备下周的项目汇报",
  "context": {
    "availableMinutes": 60
  }
}
```

响应为草稿：

```json
{
  "data": {
    "draftId": "uuid",
    "type": "task_breakdown",
    "status": "pending",
    "suggestions": [
      {
        "title": "整理汇报结构",
        "estimatedMinutes": 20
      }
    ],
    "expiresAt": "2026-09-16T10:00:00Z"
  }
}
```

### POST `/ai/drafts/{draftId}/confirm`

确认后调用普通任务/行动用例写入正式数据。

### POST `/ai/drafts/{draftId}/cancel`

取消草稿，不写入业务实体。

### GET `/ai/usage`

返回用户本周期使用量和剩余额度，不返回敏感 prompt。

## 11. 同步

### POST `/sync/push`

提交本地 outbox 操作：

```json
{
  "operations": [
    {
      "operationId": "uuid",
      "entityType": "task",
      "entityId": "uuid",
      "operationType": "update",
      "baseVersion": 4,
      "payload": {
        "title": "更新后的任务"
      }
    }
  ]
}
```

响应返回每个操作的状态：applied、already_applied、conflict、rejected。

### GET `/sync/pull`

参数：`cursor`、`limit`。

返回当前用户自游标之后的变更和新游标。

### POST `/sync/conflicts/{conflictId}/resolve`

```json
{
  "resolution": "keep_server|keep_local|manual_merge",
  "mergedPayload": {}
}
```

## 12. 数据导出和删除

### POST `/data-exports`

创建导出任务，返回任务 ID；导出可能异步完成。

### GET `/data-exports/{exportId}`

返回状态和短期下载地址。

### POST `/data-imports/preview`

上传用户导出的 JSON，先返回预览和冲突数量，不直接写入。

### POST `/data-imports/{importId}/confirm`

确认导入，支持 merge 或 replace；replace 必须二次确认。

### POST `/account/deletion-request`

发起账户删除，进入可撤销窗口后再异步清理。

## 13. API 安全与限流

- 每个请求必须做用户身份和资源归属校验。
- 列表接口强制分页和上限。
- AI 接口按用户和 IP 限流。
- 导入、导出和删除接口需要更严格限流。
- 所有外部输入使用 schema 校验。
- 错误不返回内部堆栈、SQL、密钥或完整用户数据。
- 写请求支持幂等键。
