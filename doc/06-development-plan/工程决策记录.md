## 001（2026-09-16）GitHub 仓库由私有转为公开

- 状态：已执行
- 关联：FND-006；[开发环境规范 §8](./开发环境规范.md#8-ci-与仓库可见性)；提交 `ebb2e34`；探针 PR #1

### 背景

FND-006 的验收标准是“提交一个故意失败的测试可以验证 CI 会阻止合并”。实施过程中发现：GitHub Free 个人账号下，私有仓库虽然可以保存分支保护规则，但规则被官方标记为 **Not enforced**（不强制执行）——探针 PR #1 在必需检查配置正确的情况下仍显示绿色可合并按钮。

经 GitHub 官方文档核实：分支保护在公开仓库对 Free 计划强制执行；私有仓库仅 GitHub Pro、Team、Enterprise 计划强制执行；Rulesets 存在同样的计划限制。

### 备选方案

1. **升级 GitHub Pro（约 4 美元/月）**：保持私有并解锁强制分支保护。否决原因：CI 门禁是长期固定支出，与立项书“每月现金预算约百元”的成本约束不匹配。
2. **仓库转为公开（采纳）**：Free 计划即获得服务端强制分支保护，且公开仓库的 Actions 标准 runner 分钟数免费。
3. **保持私有、不强制**：仅依靠本地 Git hooks（FND-007）和人为纪律。否决原因：无法满足 FND-006 的验收标准，服务端不阻断。

### 公开前安全评估（2026-09-16）

对全部 10 个历史提交逐版本扫描：

- 未发现私钥、云厂商密钥、GitHub/npm/AI 平台令牌；
- 真实 `.env`、证书、`node_modules`、便携运行时 `.runtime`、测试产物从未进入 Git 历史，只有不含真值的 `.env.example`；
- 命中的数据库连接串仅为 `.env.example` 格式注释和测试夹具中的本地假口令（`127.0.0.1`）；
- 未发现本机用户名、盘符绝对路径、手机号等隐私信息；
- `.git` 体积约 0.63 MB，无二进制或大文件包袱；
- 已知随公开暴露的信息：提交作者邮箱 `3529413228@qq.com`（项目负责人已知情）。

### 决策

- 仓库 https://github.com/7codeyyy-sudo/Livefil 转为 **Public**；
- **不添加 LICENSE 文件**：默认保留所有权利（All Rights Reserved），代码可被查看，但任何人无复制、修改、分发或商用的授权；
- 分支保护规则：合并 main 必须经过 PR，且 `ci-gate`、`browser-e2e` 两个检查通过、分支保持最新；规则对管理员同样生效，不可绕过。

### 影响评估

- 源代码、文档和全部 Git 历史对任何人可见；
- CI 运行日志公开：日志中不得出现密钥和真实用户数据（FND-005 已建立脱敏日志基线）；Issue、PR 讨论同样不得粘贴敏感内容；
- 依赖漏洞对公众可见，需要保持依赖更新纪律（公开仓库可免费启用 Dependabot 告警和安全更新）；
- 收益：服务端强制门禁生效（含对仓库 owner）；公开仓库 Actions 标准 runner 分钟免费；Dependabot 免费；
- 不受影响的边界：生产数据和运行时数据从不进入仓库，本次公开的仅是源代码与文档；产品本身仍维持邀请制、默认关闭公开分享，相关产品决策不变。

### 回退方式

仓库 Settings 可随时改回私有。改回后分支保护会重新变为 Not enforced 状态，若要恢复服务端强制门禁，需要升级到 GitHub Pro 或更高计划。
