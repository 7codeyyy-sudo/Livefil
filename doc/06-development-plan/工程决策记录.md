## 001（2026-09-16）GitHub 仓库由私有转为公开

- 状态：已执行
- 关联：FND-006；[开发环境规范 §8](./开发环境规范.md#8-ci-与仓库可见性)；提交 `ebb2e34`；探针 PR #1

### 背景

FND-006 的验收标准是“提交一个故意失败的测试可以验证 CI 会阻止合并”。实施过程中发现：GitHub Free 个人账号下，私有仓库虽然可以保存分支保护规则，但规则被官方标记为 **Not enforced**（不强制执行）——探针 PR #1 在必需检查配置正确的情况下仍显示绿色可合并按钮。

经 GitHub 官方文档核实：分支保护在公开仓库对 Free 计划强制执行；私有仓库仅 GitHub Pro、Team、Enterprise 计划强制执行；Rulesets 存在同样的计划限制。

### 备选方案

1. **升级 GitHub Pro（约 4 美元/月）**：保持私有并解锁强制分支保护。否决原因：CI 门禁是长期固定支出，与立项书“每月现金预算约百元”的成本约束不匹配。
2. **仓库转为公开（采纳）**：Free 计划即获得服务端强制分支保护，且公开仓库的 Actions 标准 runner 分钟数免费。
3. **保持私有、不强制**：仅依靠本地 Git hooks（FND-007）和人为纪律。否决原因：无法满足 FND-006 的验收标准，服务端不阻断。

### 公开前安全评估（2026-09-16）

对全部 10 个历史提交逐版本扫描：

- 未发现私钥、云厂商密钥、GitHub/npm/AI 平台令牌；
- 真实 `.env`、证书、`node_modules`、便携运行时 `.runtime`、测试产物从未进入 Git 历史，只有不含真值的 `.env.example`；
- 命中的数据库连接串仅为 `.env.example` 格式注释和测试夹具中的本地假口令（`127.0.0.1`）；
- 未发现本机用户名、盘符绝对路径、手机号等隐私信息；
- `.git` 体积约 0.63 MB，无二进制或大文件包袱；
- 已知随公开暴露的信息：提交作者邮箱 `3529413228@qq.com`（项目负责人已知情）。

### 决策

- 仓库 https://github.com/7codeyyy-sudo/Livefil 转为 **Public**；
- **不添加 LICENSE 文件**：默认保留所有权利（All Rights Reserved），代码可被查看，但任何人无复制、修改、分发或商用的授权；
- 分支保护规则：合并 main 必须经过 PR，且 `ci-gate`、`browser-e2e` 两个检查通过、分支保持最新；规则对管理员同样生效，不可绕过。

### 影响评估

- 源代码、文档和全部 Git 历史对任何人可见；
- CI 运行日志公开：日志中不得出现密钥和真实用户数据（FND-005 已建立脱敏日志基线）；Issue、PR 讨论同样不得粘贴敏感内容；
- 依赖漏洞对公众可见，需要保持依赖更新纪律（公开仓库可免费启用 Dependabot 告警和安全更新）；
- 收益：服务端强制门禁生效（含对仓库 owner）；公开仓库 Actions 标准 runner 分钟免费；Dependabot 免费；
- 不受影响的边界：生产数据和运行时数据从不进入仓库，本次公开的仅是源代码与文档；产品本身仍维持邀请制、默认关闭公开分享，相关产品决策不变。

### 回退方式

仓库 Settings 可随时改回私有。改回后分支保护会重新变为 Not enforced 状态，若要恢复服务端强制门禁，需要升级到 GitHub Pro 或更高计划。

### 证据

- 探针 PR #1（已关闭、未合并）：故意失败的单测使 `ci-gate` 在 29 秒内变红，两个检查均标记 Required，Merge 按钮对 owner 禁用；
- 探针分支 `ci/guard-probe` 已删除，主干 SHA 始终为 `ebb2e34`，探针代码未进入 main。

## 002（2026-10-08）装饰性背景偏好采用本机 `localStorage`，不落服务端字段

- 状态：已执行
- 关联：UI-009；《UI 页面规范》v0.24 §3.4 / §5；《开发任务清单》v0.9

### 背景

UI-009 需要让用户能切换全站装饰性背景的几何物体（四款几何 + 关闭档）。这类偏好总得存在某处。团队既有习惯是把用户偏好放到 `/me` 的服务端字段（Phase 2 的 locale/timezone/currencyCode/weekStartOn/reminderEnabled/aiEnabled 均如此），但那意味着一次跨层改动：数据库迁移 + `users` 表新列 + `UserDto` 扩字段 + `PATCH /me` 校验 + DTO 映射测试。

### 备选方案

1. **服务端字段（`/me` 扩展，沿用既有偏好模式）**：与既有偏好一致、跨设备同步。否决原因：为一项**纯显示**偏好引入 DB 迁移与 DTO/接口/校验/测试全链路改动，代价与收益（跨设备同步一个装饰性背景）严重不匹配；且项目已有红线「spike 结论若指向必须新增服务端表或与冻结契约冲突，需停止并上报」——本任务不值得触发该流程。
2. **本机 `localStorage`（采纳）**：零 DB 迁移、零接口改动、零新增依赖；仓库已有完全同构的先例 `app/(app)/_lib/guide/`（模块级快照 + `useSyncExternalStore` + 服务端快照恒 `null`，避免水合不匹配），照抄即可。语义上也成立：装饰性背景是**本机显示偏好**，与「引导进度」同属设备本机状态。
3. **不持久化（每次刷新回默认）**：否决原因：用户切换后刷新即变回，体验不成立。

### 决策

- 背景几何档位（`tesseract` / `cell24` / `clifford` / `hopf` / `none`）持久化到 `localStorage`，落 `app/(app)/_lib/appearance/`，照 `_lib/guide` 的外部存储模式实现；
- 设置页新增第 6 分区「外观」承载切换（规范 §5 v0.24 勘误补记），本分区**不参与**服务端保存、**不显示**「未保存」标记、**不进**路由离开脏页确认；
- 不新增服务端字段、不做 DB 迁移、不改 `UserDto` 与 `PATCH /me`。

### 影响评估

- 偏好**不跨设备同步**（换设备/清浏览器数据会回到默认「超立方体」）——属已知边界，与本任务「本机显示偏好」定位一致；
- 设置页出现「有的分区独立保存、有的分区即时生效且不保存」两种行为，需分区 6 的文案交代清楚（规范 §5 勘误补记已写）；
- 既有 `notification-discipline.test.ts` 对设置页分区 4 的逐字断言不受影响——分区 6 独立成文件，既有五分区分区原文零改动；
- 不触碰 doc/05 冻结契约，零依赖新增。

### 回退方式

若将来需要跨设备同步，可另立任务把该偏好提升为 `/me` 字段（届时按标准跨层流程做迁移与 DTO），`localStorage` 侧只需在读取时做一次「服务端值优先」的回落即可；当前实现不含服务端读写，回退面为零。

### 证据

- 《UI 页面规范》v0.24 §3.4 / §5 勘误补记；《开发任务清单》v0.9 UI-009；
- 代码落点 `app/(app)/_lib/appearance/` + `src/shared/ui/layout/BackgroundField/`（同构先例 `app/(app)/_lib/guide/`）。
